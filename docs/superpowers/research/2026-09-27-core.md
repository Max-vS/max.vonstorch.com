## 2. Next.js 16.1 → 16.3: what changed, and the state of each feature

Sources: https://nextjs.org/blog/next-16-2 (2026-03-18), https://nextjs.org/blog/next-16-3 (2026-08-03),
https://nextjs.org/blog/next-16-3-turbopack, https://nextjs.org/blog/next-16-3-ai-improvements,
https://nextjs.org/docs/app/guides/upgrading/version-16 (also bundled in the package).

### 2.1 Feature state in 16.3.6

| Feature | State | Details |
|---|---|---|
| `proxy.ts` (was `middleware.ts`) | Stable since 16.0. `middleware` is deprecated. | Export `function proxy(request)` (or default export). Runtime is Node.js only; `runtime` config throws. Edge runtime still needs `middleware.ts`. Place at root (or `src/`). Codemod: `bunx @next/codemod@canary upgrade latest`. Config renames: `skipMiddlewareUrlNormalize` → `skipProxyUrlNormalize`. |
| Cache Components | Stable flag `cacheComponents: true` (16.0). | Enables `"use cache"`, `cacheLife`, `cacheTag` (no `unstable_` prefix). Replaces `experimental.dynamicIO`, `experimental.useCache`, `experimental.ppr` (all removed). Uses React `<Activity>` to keep route state on navigation. Doc says: "Cache Components requires the Node.js runtime … other server-side JavaScript runtimes are not guaranteed to work." |
| Partial Prefetching | New in 16.3: `partialPrefetching: true` | Requires `cacheComponents`. Opt-in "Instant Navigations" suite. |
| `revalidateTag` | Changed in 16.0 | Needs a 2nd arg (cacheLife profile), e.g. `revalidateTag('posts', 'max')`. New `updateTag()` (Server Actions only) and `refresh()`. |
| Turbopack | Default for `next dev` and `next build` since 16.0 | `--turbopack` flag is not needed. `--webpack` opts out. Custom `webpack` config makes `next build` fail. 16.3: FS cache on by default for dev AND build (`.next/cache`), dev memory eviction on by default, `import.meta.glob` support. |
| React Compiler | Stable option `reactCompiler` since 16.0 | Not on by default. Needs `babel-plugin-react-compiler`. 16.3 adds `experimental.turbopackRustReactCompiler` (no Babel plugin needed). |
| Typed routes | Stable: top-level `typedRoutes: true` (not `experimental`) | Works with Turbopack and with TS 7 (tested). Types `Link href` and `router.push/replace/prefetch`. |
| Route type helpers | Global `PageProps<'/x'>`, `LayoutProps<'/'>`, `RouteContext` | Generated by `next dev`, `next build`, `next typegen`. The scaffold uses `LayoutProps<"/">`. |
| `next lint` | Removed in 16.0 | Run Biome/ESLint directly. `next build` no longer lints. `eslint` key in next.config removed. |
| Node.js minimum | `>=20.9.0` (`engines` of next 16.3.6) | TypeScript minimum 5.1.0. Browsers: Chrome/Edge/Firefox 111+, Safari 16.4+. |
| Async request APIs | Sync access removed in 16.0 | `params`, `searchParams`, `cookies()`, `headers()`, `draftMode()` are async only. |
| View Transitions | Work in App Router with no config (16.3 docs) | React 19.3 made `<ViewTransition>` stable. `next/link` has `transitionTypes` prop (16.2). |
| TypeScript 7 | Supported in 16.3 | `next build` runs the project-local `tsc` CLI by default (`experimental.useTypeScriptCli`, default true). |
| `next-env.d.ts` | Generated; docs say add to `.gitignore` | Now imports `.next/types/routes.d.ts` and `.next/types/root-params.d.ts`. The current repo already ignores it. |
| Dev output | `next dev` writes to `.next/dev`; lockfile `.next/dev/lock` | Dev and build can run at the same time. |
| Other 16.3 items | `catchError` (stable) from `next/error`, root params (`next/root-params`), native Node streams in SSR (+22% RPS), prefetch inlining, immutable static assets | Experimental: `useOffline` (`next/offline`), `turbopackLocalPostcssConfig`. |
| Removed in 16 | AMP, `serverRuntimeConfig`/`publicRuntimeConfig`, `devIndicators` sub-options, `unstable_rootParams`, `size`/`First Load JS` build output | |

- Docs ship inside the package: `node_modules/next/dist/docs/` (456 files, 4.1 MB). Version-matched.

`-v/--version`, `--ts/--typescript` (default), `--js/--javascript`, `--tailwind` (default), `--react-compiler`,
`--eslint`, `--biome`, `--app`, `--src-dir`, `--rspack` (adds `next-rspack`), `--import-alias <prefix/*>`,

### 3.2 Prompts (interactive, no flags)

1. What is your project named? (`my-app`)
2. Would you like to use the recommended Next.js defaults? → "Yes, use recommended defaults" (TypeScript, ESLint, Tailwind CSS, App Router, AGENTS.md) / "No, reuse previous settings" (only if saved prefs exist) / "No, customize settings".
3. Customize: TypeScript? · Which linter? ESLint / Biome / None · React Compiler? · Tailwind CSS? · `src/` directory? · App Router? (recommended) · Customize import alias? · Include AGENTS.md?

Hard-coded defaults: TS yes, linter **ESLint**, Tailwind yes, App Router yes, src no, alias `@/*`, React Compiler **no**, AGENTS.md yes.

### 3.3 Important behaviors (from source)

- If you pass any `--flag`, all prompts are skipped and the **recommended defaults** fill every option you did not pass. It prints "Using defaults for unprovided options". So you must pass `--biome` (else ESLint) and `--react-compiler` (else off).
- `--yes` uses **saved preferences** from earlier runs (file: `~/Library/Preferences/create-next-app-nodejs/config.json` on macOS), then defaults. Result depends on the machine. Do not use `--yes` for a reproducible setup. (My test: `--yes` gave Biome and no React Compiler, because an earlier run had saved `linter: biome`.)
- Package manager: from `--use-*`, else from `npm_config_user_agent`. `bunx create-next-app` and `bun create next-app` both give Bun.
- For non-npm managers it writes `"packageManager": "<pm>@<local version>"`. With `npx … --use-bun` it runs `bun --version`, so it records whatever Bun is on PATH (1.3.11 on this machine).
- For Bun it adds `"ignoreScripts": ["sharp","unrs-resolver"]` and `"trustedDependencies": ["sharp","unrs-resolver"]` (to hide Bun's blocked-postinstall warning). With Biome, `unrs-resolver` is not installed (it comes from `eslint-config-next`), and `sharp@0.35.4` has no install script. So both fields are no-ops here.
- After install it runs `bun next typegen` (route types).
- Git: skips `git init` if already inside a git repo; `--disable-git` skips it always.
- Target folder must be empty except: `.claude .cursor .DS_Store .git .gitattributes .gitignore .gitlab-ci.yml .hg .hgcheck .hgignore .idea .npmignore .travis.yml .vscode .zed LICENSE Thumbs.db docs mkdocs.yml npm-debug.log yarn-debug.log yarn-error.log yarnrc.yml .yarn *.iml`.
- Versions it writes (hard-coded in the template code): `react`/`react-dom` **"19.2.8"** (exact, not 19.3.0), `next` "16.3.6" (exact), `typescript` **"^5"** (installs 5.9.3), `@types/node` **"^20"**, `@types/react` "^19", `@types/react-dom` "^19", `@biomejs/biome` **"2.4.2"** (exact, old), `babel-plugin-react-compiler` "1.0.0", `tailwindcss` "^4", `@tailwindcss/postcss` "^4", ESLint path: `eslint` "^9" + `eslint-config-next`.
- Side effect: it saves your answers as preferences for the next run.

### 3.7 Comparison: too much / too little / sweet spot

| Option | Adds too much | Adds too little |
|---|---|---|
| Full template (no `--empty`) | Demo page, 5 SVGs, favicon, Geist fonts, color vars we replace | – |
| `--yes` | Unpredictable (saved prefs); default ESLint, no React Compiler | – |
| Manual install | – | Loose tsconfig (`strict: false`, no alias), no ignore file, no linter config, no agent files |
| **Flags + `--empty`** (sweet spot) | README text, 2 no-op Bun fields | Stale pins (react 19.2.8, TS ^5, @types/node ^20, Biome 2.4.2) → fix with 4 commands |
| `--src-dir` | Extra `src/` level; `proxy.ts`, `mdx-components.tsx`, `instrumentation.ts` must go in `src/` | – |

src vs no src: `src/` keeps config files apart from app code (root has ~12 config/agent files). No `src/` is the Next default, matches the current repo layout (`app/ components/ lib/ actions/`), and keeps `mdx-components.tsx`/`proxy.ts` at root. Tailwind v4 needs no content paths either way. Pick: no `src/`.

## 4. Bun

Sources: https://bun.com/docs/guides/ecosystem/nextjs , https://bun.com/docs/guides/deployment/vercel ,
https://bun.com/blog/bun-v1.4 , https://vercel.com/docs/functions/runtimes/bun , https://vercel.com/docs/package-managers

### 4.1 Bun 1.4 (2026-08-20; latest 1.4.2 on 2026-09-05)
- Rewrite from Zig to Rust. Reports Node.js 26 compatibility.
- "Upgrading to 1.4" breaking items: `process.versions.modules` = 147 (native addons need a build for 147); `res.writeHeader()` removed; paused `readable.read()` returns one chunk; **new monorepos** default to isolated linker (`bun.lock` records `configVersion: 1`); **Bun run as `node` (`bun --bun`, `bunx --bun`) no longer loads `.env` files** (pass `--env-file`); `Bun.YAML` is YAML 1.2; `bun.lock`/`bunfig.toml` TOML is strict.
- Blog: "`bun --bun next build` works on Next.js 16.3 with Turbopack and the React Compiler."
- New lockfile: `"lockfileVersion": 2`. **Bun 1.3.x cannot read it** (tested: `error: Unknown lockfile version … warn: Ignoring lockfile`).

### 4.2 `bun --bun next …` or plain `next …`?

| Source | Says |
|---|---|
| Bun Next.js guide | Use `bun --bun next dev/build/start` (Bun runtime). |
| Next.js docs | Plain `next dev/build/start`; `bun dev`, `bun create next-app`, `bunx next upgrade`. Cache Components doc: needs Node.js runtime; other runtimes "not guaranteed to work". Bun listed as a "verified adapter" for self-hosting. |
| Vercel docs | Functions run on Node.js by default. Bun runtime is **Beta**: needs `"bunVersion": "1.4.x"` (or `"1.x"` = 1.3.14) in `vercel.json`; with Next.js + ISR you must change `dev`/`build` to `bun run --bun next …`. Bun runtime lacks automatic source maps and `node:http` request metrics. |

**Conflict.** Pick: plain `next …` (Node.js runtime), Bun only installs packages and runs scripts. Reasons: Next docs and Cache Components want Node; Vercel Bun runtime is Beta; Bun-runtime builds of Next 16.3 crashed on Bun <= 1.3.14 (issues oven-sh/bun#36866, #26508; fixed in 1.4.0 per reports); speed gain is tiny here.
How it works: `bun run build` runs the `next` bin, whose shebang is `#!/usr/bin/env node`, so Node runs it. Only `--bun` forces Bun.

Local measurements (site-a, 300-tile page, cold `.next`):
- `bun run build` → `[config] runtime: node v25.8.1`, 3.00 s.
- `bun --bun next build` → `[config] runtime: bun 1.4.2`, 2.69 s.
- `next dev` works under both; page returns 200 with 300 `<rect>`.
- `cacheComponents: true` + `"use cache"` + `cacheLife("hours")` builds under both (route shows revalidate 1h / expire 1d).

### 4.3 Vercel build image and the Bun 1.4 lockfile (RISK)
- Vercel picks Bun from `bun.lock`. Docs do not state the build image's Bun version.
- Issue vercel/vercel#17577 (closed 2026-09-15): build container ran bundled Bun 1.3.x, ignored the v2 `bun.lock` (silent full re-resolve), and `bunVersion` / `packageManager` / `.bun-version` had no effect on install. A Vercel maintainer wrote "Fixed and released in 59.17.0 … on the build container"; a comment on 2026-09-18 said it was not deployed yet. PR #17608 was closed unmerged (fix ported internally).
- UNVERIFIED: whether the fix is live today.
- Check: in the first Vercel build log, read the `bun install vX.Y.Z` line and look for "Ignoring lockfile".
- Fallback (from affected projects): `vercel.json` → `{ "installCommand": "bunx bun@1.4.2 install --frozen-lockfile" }`.

### 4.4 Bun + TypeScript
Bun docs recommend `@types/bun` and a Bun tsconfig (`module: "Preserve"`, `allowImportingTsExtensions`, `verbatimModuleSyntax`, `types: ["bun"]`). This conflicts with the Next-managed tsconfig. Pick: do not add `@types/bun` or Bun tsconfig options; we do not call Bun APIs in app code.

## 5. React and React Compiler

Sources: https://react.dev/blog/2026/09/09/react-19-3 , https://react.dev/blog/2025/10/07/react-compiler-1 ,
https://nextjs.org/docs/app/api-reference/config/next-config-js/reactCompiler ,
https://nextjs.org/docs/app/api-reference/config/next-config-js/turbopackRustReactCompiler ,
https://github.com/react/react/pull/36173 , https://www.infoq.com/news/2026/07/meta-react-compiler-rust/

### 5.1 React 19.3 (2026-09-09)
- Stable `<ViewTransition>` + `addTransitionType` (DOM only). Only Transition updates animate.
- Fragment refs (`<Fragment ref>` → `FragmentInstance` with `observeUsing`, `focus`, `getClientRects`, …).
- `browser()` from `react-dom` (skip SSR for a subtree via Suspense).
- Trusted Types support; Server Components can render Context directly (`<Ctx value>`).
- No breaking changes listed. No React 20.
- Next 16.3.6 App Router uses bundled `19.3.0-canary-cbb046ab-20260731`. Next docs still say: declare `react`/`react-dom` in package.json (used by Pages Router and tooling). create-next-app pins 19.2.8 → bump to 19.3.0 (Next manual-install docs use `react@latest`).

### 5.2 React Compiler status
- `babel-plugin-react-compiler@1.0.0` (stable since 2025-10-07) is still the latest.
- Next 16 made `reactCompiler` a stable top-level option. It is **off by default** "as we continue gathering build performance data". Next runs it only on files with JSX or hooks (SWC pre-filter).
- Options in Next types: `compilationMode: 'infer' | 'annotation' | 'all'`, `panicThreshold: 'none' | 'critical_errors' | 'all_errors'`. Directives: `"use memo"`, `"use no memo"`.
- Rust port of the compiler merged into the React repo in mid-2026 (PR #36173, "experimental, work-in-progress"). Next 16.3 uses it via `experimental.turbopackRustReactCompiler: true` (requires `reactCompiler: true`; Turbopack only; no Babel plugin needed). Next reports 34% (cold) / 46% (warm) faster `next dev` time-to-ready on v0.
- Build-time cost measured here (cold builds, 3 runs each): no compiler 2.64–2.72 s; Babel 2.70–3.27 s (one outlier 4.75 s); Rust 2.83–3.30 s. Difference is noise for this site.

### 5.3 Is it good for the tile grid (~150–300 memoized SVG tiles)? Yes.
I compiled a 300-tile test component with the compiler (Babel 7, same as Next uses). Output:
- `Tile` caches its callback and its `<rect>` element by props. When props do not change, it returns the same element, so React skips that DOM subtree.
- `TileGrid` caches the tile array and the whole `tiles.map(...)` result; the map re-runs only when `active` or `tiles` change. Then all 300 `Tile` functions run, but only tiles with changed props produce new elements.
- So: the compiler gives most of the benefit of `React.memo` + `useCallback` with no manual code. `memo(Tile)` is still allowed if we want to skip the 300 function calls; it is not needed at this size.
Advice for the grid: keep hover and animation in CSS (`transition`, `:hover`, `data-*` attributes). Change React state only on real events (click, route change). Do not drive per-frame animation through React state.

### 5.4 Compiler diagnostics without ESLint
- The compiler skips components it cannot compile, without a message (`panicThreshold: 'none'`).
- Biome 2.5.14 has a nursery rule `lint/nursery/useReactCompiler` ("Validate files with React Compiler"). I tested it: it flags ref reads/writes during render. Enable with `"linter": { "rules": { "nursery": { "useReactCompiler": "error" } } }`. Nursery = may change. (Biome agent to confirm.)
- Gotcha: `babel-plugin-react-compiler@1.0.0` run under **Babel 8** (`@babel/core@8.0.6` is now npm latest) bailed out on a function with default-valued destructured params (`Todo … AssignmentPattern`). Under Babel 7 it compiled fine. Next bundles Babel 7, so Next is not affected. Only matters for standalone Babel/Vitest setups.

## 6. TypeScript

Sources: https://devblogs.microsoft.com/typescript/announcing-typescript-7-0/ (2026-07-08),
https://nextjs.org/docs/app/api-reference/config/typescript#using-typescript-7 ,
https://nextjs.org/docs/app/api-reference/config/next-config-js/useTypeScriptCli

- TS 7.0 = native Go port, package name `typescript`, binary `tsc`. 8–12x faster full builds.
- No JS compiler API in 7.0 (package main export is only `lib/version.cjs`; `unstable/*` exports exist). TS team expects a new API in 7.1.
- **No language-service plugins** in TS 7. So the Next.js TS plugin (`"plugins": [{ "name": "next" }]`) does not run in the editor under TS 7. Tools that embed TS (MDX, Vue, Svelte, Astro) "can only currently rely on TypeScript 6.0".
- Removed options: `target: es5`, `baseUrl`, `moduleResolution: node/node10/classic`, `module: amd/umd/system/none`, `esModuleInterop:false`, `allowSyntheticDefaultImports:false`. I confirmed `baseUrl` gives `error TS5102: Option 'baseUrl' has been removed`.
- Next 16.3: `next build` runs project-local `tsc` by default (`experimental.useTypeScriptCli`, default true). Diagnostics are raw `tsc` output (no Next code frames). The whole tsconfig project is checked; `--debug-build-paths` does not narrow it.
- Tests (site-f-ts7): `next build` with TS 7.0.2 passes; type check 0.18–0.20 s vs 0.64–0.80 s with TS 5.9.3; a bad assignment fails the build (`TS2322`); `typedRoutes` typo fails the build (`TS2820 … Did you mean "/writing"?`); `bun next typegen && tsc --noEmit` passes.
- Editor: VS Code uses the TS 7 native language server (native preview extension / built-in rollout). Exact VS Code setting: UNVERIFIED.
- Pick: `typescript@^7`. Fallback: `typescript@^6` (6.0.3) if we need the Next TS plugin hints or MDX type-aware editor tooling. `@typescript/typescript6` exists for side-by-side use.

## 8. Gotchas and changes vs 2024–2025 knowledge

1. No `--turbopack` in scripts; Turbopack is default. `--webpack` opts out. `next build` fails if a `webpack` config exists.
2. `middleware.ts` → `proxy.ts`, function `proxy`, Node runtime only.
3. `next lint` is gone. `next build` does not lint.
4. `experimental.dynamicIO/useCache/ppr` removed → `cacheComponents`. `unstable_cacheLife/cacheTag` → `cacheLife/cacheTag`. `revalidateTag(tag, profile)` needs 2 args.
5. `typedRoutes` is top-level (not experimental).
6. `reactCompiler` is top-level (not experimental).
7. `next-env.d.ts` should be git-ignored; it now imports `.next/types/*`.
8. `next dev` writes to `.next/dev`; AGENTS.md/CLAUDE.md get re-created under AI agents (`agentRules`).
9. Next docs ship in `node_modules/next/dist/docs/` — the best source for agents.
10. `create-next-app --yes` = saved preferences, not fixed defaults. Any flag = defaults for the rest (ESLint, no compiler).
11. create-next-app pins old versions (React 19.2.8, TS ^5, @types/node ^20, Biome 2.4.2). Bump after scaffold.
12. TS 7: no `baseUrl`, no LS plugins, no JS API. Next handles it with the `tsc` CLI.
13. Bun 1.4 lockfile v2 is unreadable by Bun 1.3.x (local and possibly Vercel build image).
14. Bun 1.4 `--bun` does not load `.env` (Next loads `.env*` itself, so Next is fine; standalone scripts are not).
15. Local Node 25 is EOL; Vercel has no Node 25/26; use 24.x.
16. Scroll: Next 16 no longer overrides `scroll-behavior: smooth`; add `data-scroll-behavior="smooth"` on `<html>` to get the old behavior.
17. Parallel route slots need `default.tsx`.
18. `images` defaults changed in 16 (`minimumCacheTTL`, `qualities`, local IP block, max redirects, local images with query strings).
19. With `cacheComponents: true`, the segment configs `export const dynamic` and `export const dynamicParams` fail the build: `Route segment config "dynamic" is not compatible with nextConfig.cacheComponents. Please remove it.` (reported by research-content; I confirmed both in site-j-verify). Without them, `generateStaticParams` + `[slug]` builds: known slugs are static (○), unknown slugs get a partial prerender shell (◐).
20. `import.meta.glob` (Turbopack, new in 16.3) silently returns `{}` for patterns that go up a folder (`'../…'`) in 16.3.6. Same-folder patterns (`'./…'`) work. (Reported by research-content with fix vercel/next.js#96557 on canary only; I confirmed `parent=0 local=1` in site-j-verify.) Keep globbed content below the importing file, or use `fs` reads.
