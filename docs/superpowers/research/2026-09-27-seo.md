# SEO research: max.vonstorch.com rewrite

- Date: 2026-09-27. Research only. No project files changed.
- Target stack: Next.js 16.3 (App Router, Cache Components, Turbopack), React 19.3, Vercel Hobby.
- Goal: rank #1 for "Max von Storch" (plus "Max vonStorch", maybe "Maximilian von Storch") and get the MDX articles indexed.
- Doc versions checked: every Next.js page fetched shows `version: 16.3.6`. The "last updated" date of each Google/Vercel page is in section 9.
- Labels: **MUST** = blocks name ranking or indexing. **SHOULD** = clear gain. **NICE** = small or optional. **UNVERIFIED** = I could not confirm it from a primary source.

---

## 0. Short version

1. The live site has no name in `<title>` (it is "MvS"). It has no structured data and no OG tags. It has only an SVG favicon, which is not a format that Google Search lists. The sitemap has 1 URL with a fake `lastmod`. The GitHub profile has no website link.
2. For the rewrite, the MUST items are: a name-first title and template, a self-canonical per page (not in the root layout), static metadata in `<head>`, a full `sitemap.ts`, WebSite + ProfilePage + Person JSON-LD on `/`, ICO/PNG favicons, server-rendered text with crawlable links, `generateStaticParams` for posts, and a 308 redirect for the public `maxvonstorchcom.vercel.app` alias.
3. Off-site order: deploy the fixes. Then verify in Search Console (Domain property `vonstorch.com` through a DNS TXT record at IONOS). Then submit the sitemap. Then use URL Inspection and Request indexing. Then add the site URL to GitHub, LinkedIn, and X. Then import the site into Bing Webmaster Tools.

## 2. Prioritized checklist for the new site

Format for each item: what to do, why (1 line), the Next.js 16 API or file, and sources.

### MUST

**M1. Name-first titles with a template.**
- Why: `<title>` is the main input for title links. Google says: be descriptive, avoid "Home", and brand concisely with a delimiter ([title links](https://developers.google.com/search/docs/appearance/title-link), [SEO starter guide](https://developers.google.com/search/docs/fundamentals/seo-starter-guide)).
- How: in the root `app/layout.tsx`, set `title: { default: 'Max von Storch', template: '%s | Max von Storch' }`. On the home page (`app/page.tsx`), set `title: { absolute: 'Max von Storch – Founding Engineer at Dryft, San Francisco' }`.
- Note: `title.template` applies only to **child** segments. It does not apply to a `page.js` in the same segment as the layout, so the home page must set its full title ([generateMetadata: template](https://nextjs.org/docs/app/api-reference/functions/generate-metadata#template)).
- Keep the same wording in the H1, `og:title`, and `og:site_name`. Google checks consistency for site names ([site names](https://developers.google.com/search/docs/appearance/site-names)).

**M2. A unique meta description on each page.**
- Why: Google sometimes uses it for the snippet. Use a site-level description on the home page ([snippets](https://developers.google.com/search/docs/appearance/snippet)).
- How: `description` in each page's `metadata`. Put the name, role, Dryft, San Francisco, and TU Munich in the home description.

**M3. `metadataBase` plus a self-referential canonical on every page. Do not put the canonical in the root layout.**
- Why: Google recommends a self canonical with an **absolute** URL. The canonical must be in `<head>` ([canonical](https://developers.google.com/search/docs/crawling-indexing/consolidate-duplicate-urls)). Next resolves relative paths against `metadataBase` and gives a build error without it ([metadataBase](https://nextjs.org/docs/app/api-reference/functions/generate-metadata#metadatabase)).
- How: root layout `metadataBase: new URL('https://max.vonstorch.com')`. Hard-code it. Do not derive it from `VERCEL_URL`. Each page sets `alternates: { canonical: '/projects' }`.
- Caution: metadata merges **shallowly**. A page that sets `alternates` or `openGraph` replaces the parent object completely ([merging](https://nextjs.org/docs/app/api-reference/functions/generate-metadata#merging)). Use one helper for all pages (see the code below).

**M4. Keep all metadata static or cached, so it is in the initial HTML `<head>`.**
- Why: prerendered pages resolve metadata at build time and do not stream it ([Metadata & OG images](https://nextjs.org/docs/app/getting-started/metadata-and-og-images)). Dynamic `generateMetadata` output is streamed and appended to `<body>`. Next says Googlebot reads it correctly ([streaming metadata](https://nextjs.org/docs/app/api-reference/functions/generate-metadata#streaming-metadata)). But Google says `rel=canonical` "is only accepted if it appears in the `<head>`" ([canonical](https://developers.google.com/search/docs/crawling-indexing/consolidate-duplicate-urls)). Avoid the conflict (section 7).
- How: use `export const metadata` on static pages. On posts, use `generateMetadata` with `'use cache'` plus `generateStaticParams` (M10). Never read `cookies()`, `headers()`, or `searchParams` in metadata. Leave `htmlLimitedBots` at its default.

**M5. `app/robots.ts`: allow everything and list the sitemap.**
- Why: robots.txt controls crawling, not indexing. Do not block assets Google needs to render the page ([maintaining SEO](https://developers.google.com/search/docs/fundamentals/get-started), [JS SEO](https://developers.google.com/search/docs/crawling-indexing/javascript/javascript-seo-basics)).
- How: `MetadataRoute.Robots` ([robots.ts](https://nextjs.org/docs/app/api-reference/file-conventions/metadata/robots)). Do **not** add `VERCEL_ENV`-based `Disallow: /` logic. Vercel already sends noindex on previews, and a wrong env check can block production. Do not disallow `/_next/`.

**M6. `app/sitemap.ts` with all 8 routes and all posts, using real dates.**
- Why: use absolute URLs, and list only canonical URLs. `lastmod` must be accurate. `priority` and `changefreq` are ignored ([build sitemap](https://developers.google.com/search/docs/crawling-indexing/sitemaps/build-sitemap)).
- How: `MetadataRoute.Sitemap` ([sitemap.ts](https://nextjs.org/docs/app/api-reference/file-conventions/metadata/sitemap)). For posts, take `lastModified` from frontmatter (`updated ?? date`). For static pages, use a maintained date or omit it. Never use `new Date()`. Use the same URL form as the canonicals (no trailing slash, same host).
- Note: sitemap.ts is a special Route Handler. It stays static unless it uses request-time APIs ([route handlers](https://nextjs.org/docs/app/getting-started/route-handlers)).

**M7. JSON-LD on `/`: WebSite (site name) + ProfilePage + Person.**
- Why, WebSite: "WebSite structured data is most important" for the site name. It must be on the home page. Subdomains are supported. Give `alternateName` in order of preference, and the lowercase host as the last fallback ([site names](https://developers.google.com/search/docs/appearance/site-names)).
- Why, ProfilePage: it is Google's documented type for a page whose "primary focus … must be a single person or organization that is affiliated with the overall website". Valid uses include an "About Me" page. Required: `mainEntity`, with `name` on the Person. Recommended: `alternateName`, `description`, `image`, `sameAs`, `dateCreated`, `dateModified` ([ProfilePage, updated 2026-09-08](https://developers.google.com/search/docs/appearance/structured-data/profile-page)). I found **no** separate "Person" rich-result doc in Google's docs. So: use ProfilePage with a Person as `mainEntity`. Do not use Organization for a person ([Article author practices](https://developers.google.com/search/docs/appearance/structured-data/article)).
- `image`: only a real photo. Google says: "don't include a default image, icon, or placeholder" ([ProfilePage](https://developers.google.com/search/docs/appearance/structured-data/profile-page)).
- The marked-up facts must be visible on the page ([structured data policies](https://developers.google.com/search/docs/appearance/structured-data/sd-policies)).
- How: a native `<script type="application/ld+json">` in `app/page.tsx`, escaped with `.replace(/</g, '\\u003c')`. Do not use `next/script` ([Next JSON-LD guide](https://nextjs.org/docs/app/guides/json-ld)). Validate with the [Schema Markup Validator](https://validator.schema.org/). The Rich Results Test does not support site names ([site names](https://developers.google.com/search/docs/appearance/site-names)).
- Expected result: better entity understanding and author linking. No guaranteed visual SERP feature ([ProfilePage troubleshooting](https://developers.google.com/search/docs/appearance/structured-data/profile-page)).

**M8. Favicons in formats that Google lists.**
- Why: the icon must be square and at least 8×8. Google recommends more than 48×48. Formats: BMP, GIF, ICO, PNG, JPEG, PPM, TIFF. It must be linked from the home page `<head>`, crawlable by Googlebot-Image, and have a stable URL. One icon per hostname; subdomains are supported ([favicon](https://developers.google.com/search/docs/appearance/favicon-in-search)).
- How: `app/favicon.ico` (include 48×48), `app/icon.png` (for example 192×192), and `app/apple-icon.png` (180×180). Next generates the `<link>` tags ([app icons](https://nextjs.org/docs/app/api-reference/file-conventions/metadata/app-icons)). Remove `metadata.icons`, which points to the SVG. File-based metadata overrides it anyway ([generateMetadata note](https://nextjs.org/docs/app/api-reference/functions/generate-metadata)).

**M9. All text is server-rendered, and all links are real `<a href>` elements. Use one clear H1 per page.**
- Why: "Google can only discover your links if they are `<a>` HTML elements with an `href` attribute" ([JS SEO](https://developers.google.com/search/docs/crawling-indexing/javascript/javascript-seo-basics), [crawlable links](https://developers.google.com/search/docs/crawling-indexing/links-crawlable)). "Put key information in text, not graphics" ([maintaining SEO](https://developers.google.com/search/docs/fundamentals/get-started)).
- How: the persistent nav uses `next/link` with visible text. The decorative grid (`aria-hidden`) contains no links and no content.
- H1: Google says the number and order of headings "doesn't matter" for Search ([SEO starter guide](https://developers.google.com/search/docs/fundamentals/seo-starter-guide)). But Google does rewrite title links when a page has "no clear main title" or "multiple headings with equal visual weight" ([title links](https://developers.google.com/search/docs/appearance/title-link)).
- Pattern for the persistent layout: the layout renders the name as a `<p>` or a home link, not as an `<h1>`. Each page renders exactly one `<h1>`: on `/` "Max von Storch", on subpages "Projects" and so on, on posts the post title. In `mdx-components.tsx`, map MDX `h1` to `h2`, so a post body cannot add a second H1.

**M10. Posts at `/writing/[slug]`: prerender them and give each full metadata.**
- `generateStaticParams` returns every slug. With Cache Components it must return **at least one** param, because an empty array is a build error ([generateStaticParams](https://nextjs.org/docs/app/api-reference/functions/generate-static-params#with-cache-components)).
- `generateMetadata` uses `'use cache'` and `await params`. This is the documented pattern ([runtime data in generateMetadata](https://nextjs.org/docs/messages/blocking-prerender-metadata-runtime)). The return value must be serializable: return `metadataBase` as a string, not a `URL` ([metadataBase note](https://nextjs.org/docs/app/api-reference/functions/generate-metadata#metadatabase)).
- JSON-LD `BlogPosting` with `headline`, `datePublished`, `dateModified`, `image`, and `author: { "@type": "Person", name: "Max von Storch", url: "https://max.vonstorch.com/" }`. Google: when `author.url` is an internal profile page, mark up that page with ProfilePage ([Article](https://developers.google.com/search/docs/appearance/structured-data/article)).
- Unknown slugs: `dynamicParams` is **removed** when Cache Components is on ([route segment config](https://nextjs.org/docs/app/api-reference/file-conventions/route-segment-config)), so `export const dynamicParams = false` from the [MDX guide](https://nextjs.org/docs/app/guides/mdx) does not apply. Call `notFound()` in the page. With Cache Components the static shell streams first. So the result is a **200 with `<meta name="robots" content="noindex">`** (soft 404, kept out of the index), not a 404 status ([notFound](https://nextjs.org/docs/app/api-reference/functions/not-found), [loading.js status codes](https://nextjs.org/docs/app/api-reference/file-conventions/loading)). For a real 404, see S5.

**M11. Redirect the public production alias `maxvonstorchcom.vercel.app` to the custom domain.**
- Why: it serves a full duplicate with no noindex (audit #12). A redirect is the strongest canonical signal ([canonical](https://developers.google.com/search/docs/crawling-indexing/consolidate-duplicate-urls)). Vercel documents this exact fix ([Vercel redirects](https://vercel.com/docs/routing/redirects)).
- How: in `next.config.ts`, add `redirects()` with `has: [{ type: 'host', value: 'maxvonstorchcom\\.vercel\\.app' }]` and `permanent: true`. This gives a 308. The same rule in `vercel.json` also works. Do not match preview hosts.

**M12. Verify the build output before and after the deploy.** Use the command list at the end of this section.

### SHOULD

**S1. OG and Twitter images per page (`next/og`).**
- Why: they make the link previews on LinkedIn, X, and Slack. They are not a Google ranking factor. The size limits are 8 MB (OG) and 5 MB (X). The build fails if an image is larger ([opengraph-image](https://nextjs.org/docs/app/api-reference/file-conventions/metadata/opengraph-image)).
- How: `app/opengraph-image.tsx` (the site default) plus `opengraph-image.tsx` in each route folder, plus `app/writing/[slug]/opengraph-image.tsx`. Export `alt`, `size = { width: 1200, height: 630 }`, and `contentType`. Add `twitter-image.tsx` (a re-export of the OG file is **UNVERIFIED**; if it fails, copy the file) and set `twitter: { card: 'summary_large_image' }` in the root metadata. Generated images are static at build time. In a dynamic segment the image depends on `params`, so pair it with `generateStaticParams` ([blocking-prerender-metadata-runtime gotchas](https://nextjs.org/docs/messages/blocking-prerender-metadata-runtime)).
- Font limits for `ImageResponse`: "Maximum bundle size of 500KB". Only `ttf`, `otf`, and `woff` fonts work ([ImageResponse](https://nextjs.org/docs/app/api-reference/functions/image-response)). The current HelveticaNeue OTFs are 260–630 KB each. Use a Latin subset for the OG font.

**S2. RSS feed.**
- How: `app/rss.xml/route.ts` returns XML with `Content-Type: application/rss+xml; charset=utf-8`. This is the documented "Non-UI Responses" pattern ([route.js](https://nextjs.org/docs/app/api-reference/file-conventions/route)). Add autodiscovery with `alternates: { types: { 'application/rss+xml': 'https://max.vonstorch.com/rss.xml' } }` ([alternates](https://nextjs.org/docs/app/api-reference/functions/generate-metadata#alternates)). Put it in the shared helper, because of the shallow merge.
- Cache Components: a GET handler stops prerendering on async file-system reads. Move the post loading into a helper function with `'use cache'`. `'use cache'` cannot be used directly in the handler body ([route handlers with Cache Components](https://nextjs.org/docs/app/getting-started/route-handlers)).
- Google accepts RSS 2.0 and Atom 1.0 as sitemaps. You can submit the feed in GSC too ([build sitemap](https://developers.google.com/search/docs/crawling-indexing/sitemaps/build-sitemap)).

**S3. Internal linking.**
- The nav links to all 8 routes on every page, with text anchors. `/writing` links to every post. Each post links to `/writing`, to `/`, and to related posts. The home page links to the latest posts, which gives fresh posts a path from the strongest page. Always link to canonical URLs ([canonical: link consistently](https://developers.google.com/search/docs/crawling-indexing/consolidate-duplicate-urls), [link text](https://developers.google.com/search/docs/crawling-indexing/links-crawlable)).

**S4. Core Web Vitals for the decorative grid.** See section 4. Targets: LCP ≤ 2.5 s, INP < 200 ms, CLS < 0.1 ([CWV](https://developers.google.com/search/docs/appearance/core-web-vitals)).

**S5. A real 404 status for unknown slugs (optional).**
- Next: "run that check in `proxy`" to rewrite missing slugs to a not-found route or to return a 404 ([notFound](https://nextjs.org/docs/app/api-reference/functions/not-found), [loading.js](https://nextjs.org/docs/app/api-reference/file-conventions/loading)).
- How: `proxy.ts` with a static set of slugs generated at build. The soft 404 with noindex from M10 is acceptable for SEO. GSC can report it as a soft 404 ([Page indexing report](https://support.google.com/webmasters/answer/7440203)).

**S6. Visible identity text and a photo on `/`.**
- The home page text states: full name, "founding engineer at Dryft", "San Francisco", "studied at TU Munich". Add links to Dryft and TUM. Add a real headshot with `alt="Max von Storch"`. Use `next/image` with `fetchPriority="high"` if it is above the fold. `priority` is deprecated in 16 ([next/image](https://nextjs.org/docs/app/api-reference/components/image)).
- Google: add images near relevant text, and write descriptive alt text ([SEO starter guide](https://developers.google.com/search/docs/fundamentals/seo-starter-guide)). The same photo URL can be the Person `image`.

**S7. One consistent site name.**
- `og:site_name`, the WebSite `name`, the home `<title>`, and the H1 all use "Max von Storch". "MvS" goes in `alternateName` only ([site names](https://developers.google.com/search/docs/appearance/site-names)).

**S8. Remove the global `robots: { index: true, follow: true, googleBot: … }`.**
- It is the default ("all"). It also adds a second, conflicting robots tag on 404 pages ([robots meta](https://developers.google.com/search/docs/crawling-indexing/robots-meta-tag)).

**S9. Name variants.**
- Put "Max vonStorch" in the Person `alternateName` only if you actually use that spelling.
- Add "Maximilian" only if it is the owner's legal name, and show it visibly (for example on `/cv`: "Maximilian (Max) von Storch"). The visible-content rule applies ([sd-policies](https://developers.google.com/search/docs/appearance/structured-data/sd-policies)).
- The "Maximilian von Storch" query is shared with at least one other person (audit #17), so #1 for that query is not realistic to guarantee.

### NICE

- **N1.** Add `BreadcrumbList` on posts (Home › Writing › Post). The breadcrumb is otherwise inferred from the URL ([SEO starter guide](https://developers.google.com/search/docs/fundamentals/seo-starter-guide)).
- **N2.** Get field CWV data from Vercel Speed Insights, or from the GSC CWV report once there is enough traffic. That report depends on CrUX data. A low-traffic site may show no data (**UNVERIFIED** threshold).
- **N3.** Leave `htmlLimitedBots` at its default. Override only with a reason ([htmlLimitedBots](https://nextjs.org/docs/app/api-reference/config/next-config-js/htmlLimitedBots)).
- **N4.** IndexNow: Bing, Yandex, Naver, Seznam, Yep, and Amazon take part. **Google does not** ([indexnow.org FAQ](https://www.indexnow.org/faq)). For a personal site with rare updates, the Bing Webmaster Tools sitemap is enough.
- **N5.** Apex `vonstorch.com`: if the family agrees, replace the Sedo parking page with a 301/308 redirect to `https://max.vonstorch.com/`. Keep the IONOS MX records. This is optional. **UNVERIFIED** that it helps ranking.
- **N6.** Do not block AI or search crawlers in robots.txt. `Google-Extended` "does not impact a site's inclusion in Google Search nor is it used as a ranking signal" ([Google crawlers](https://developers.google.com/crawling/docs/crawlers-fetchers/google-common-crawlers)).
- **N7.** Knowledge panel: if one appears for the name later, claim it with "Get verified on Google" ([Knowledge Panel help](https://support.google.com/knowledgepanel/answer/7534902?hl=en)). You cannot create one on request.

### Code sketch (for implementers)

```ts
// lib/site.ts
export const SITE_URL = 'https://max.vonstorch.com'
```

## 3. What Cache Components changes for metadata (Next 16.3)

1. **Runtime data in metadata is an error.** If `generateMetadata` (or file-based metadata) reads `cookies()`, `headers()`, `params`, or `searchParams` while the rest of the route is prerenderable, the build errors. The fixes: static metadata, `generateStaticParams` + `'use cache'`, or a Suspense-wrapped `connection()` "dynamic marker" ([generate-metadata: With Cache Components](https://nextjs.org/docs/app/api-reference/functions/generate-metadata#with-cache-components), [error page](https://nextjs.org/docs/messages/blocking-prerender-metadata-runtime)). For SEO, choose the static options.
2. **Uncached data in metadata** (fetch, DB, `connection()`) has its own error and fixes ([blocking-prerender-metadata-dynamic](https://nextjs.org/docs/messages/blocking-prerender-metadata-dynamic)).
3. **`'use cache'` in `generateMetadata`**: return serializable values. `URL` objects are not supported, so give `metadataBase` as a string ([metadataBase](https://nextjs.org/docs/app/api-reference/functions/generate-metadata#metadatabase)).
4. **The root layout's `generateMetadata`** is inherited by `/_not-found` and `/_global-error`, which must be static. So keep root metadata static ([error page gotchas](https://nextjs.org/docs/messages/blocking-prerender-metadata-runtime)).
5. **A `title.template` in a parent layout** is applied at build time. It adds no dynamic dependency (same source).
6. **Dynamic segments**: `generateStaticParams` must return at least 1 param. `dynamicParams` is removed. Params that are not listed render on the first request and are then saved ([dynamic routes](https://nextjs.org/docs/app/api-reference/file-conventions/dynamic-routes#with-cache-components), [route segment config](https://nextjs.org/docs/app/api-reference/file-conventions/route-segment-config)).
7. **`notFound()` after the shell streams** gives a 200 plus noindex. For a real 404, check in `proxy` ([notFound](https://nextjs.org/docs/app/api-reference/functions/not-found)).
8. **`Date.now()` / `new Date()` / `Math.random()` during prerender** raise errors. This includes Suspense fallbacks and `not-found.js`. Example: a copyright year needs a `'use cache'` + `cacheLife('max')` helper ([current-time error](https://nextjs.org/docs/messages/blocking-prerender-current-time)). A decorative grid that randomizes in render hits the `Math.random()` variant.
9. **Special route handlers** (`sitemap.ts`, `robots.ts`, `opengraph-image.tsx`, `icon.tsx`) stay static by default. Normal GET handlers (such as `rss.xml`) follow the page prerender model ([route handlers](https://nextjs.org/docs/app/getting-started/route-handlers)).
10. **Streaming metadata and bots.** Googlebot is treated as a JS-executing bot. It gets streamed metadata for **dynamic** pages. HTML-limited bots get blocking metadata in `<head>`. These include Bingbot, DuckDuckBot, Applebot, LinkedInBot, Twitterbot, facebookexternalhit, Slackbot, and all `Google-*` / `*-Google` agents ([htmlLimitedBots](https://nextjs.org/docs/app/api-reference/config/next-config-js/htmlLimitedBots), [source: html-bots.ts](https://github.com/vercel/next.js/blob/canary/packages/next/src/shared/lib/router/utils/html-bots.ts), [is-bot.ts](https://github.com/vercel/next.js/blob/canary/packages/next/src/shared/lib/router/utils/is-bot.ts)). Consequence from reading the source: GSC URL Inspection and the Rich Results Test use `Google-InspectionTool` ([Google crawlers](https://developers.google.com/crawling/docs/crawlers-fetchers/google-common-crawlers)). That UA matches the HTML-limited regex, so those tools can see `<head>` metadata that real Googlebot gets streamed into `<body>`. **UNVERIFIED in practice**; it is inferred from the canary source. It does not matter if all metadata is static (M4).

## 4. Core Web Vitals notes for a JS-heavy decorative grid

Targets: LCP ≤ 2.5 s, INP < 200 ms, CLS < 0.1 ([Google CWV](https://developers.google.com/search/docs/appearance/core-web-vitals)).

**LCP**
- A standalone `<svg>` is **not** an LCP candidate. `<image>` inside an SVG, `<img>`, and block-level text are candidates. So the LCP is likely the name or title text, or a headshot ([web.dev LCP](https://web.dev/articles/lcp)).
- Elements with `opacity: 0` are ignored until they are visible. A JS fade-in of the title block therefore delays the LCP ([web.dev LCP](https://web.dev/articles/lcp)).
- Fonts: preload only the 1 weight used above the fold. Set `preload: false` on the others. Use WOFF2 in `next/font/local`. `display` defaults to `'swap'` ([next/font](https://nextjs.org/docs/app/api-reference/components/font)). The live site preloads 6 OTF files, about 1.15 MB with brotli (audit #16).
- For a hero photo, use `next/image` with `fetchPriority="high"` or `loading="eager"` ([next/image](https://nextjs.org/docs/app/api-reference/components/image)).

**INP**
- Break up long tasks. Keep the DOM small, because rendering cost scales with DOM size. Avoid layout thrashing. Defer non-critical work with `requestAnimationFrame`. Use `content-visibility` for offscreen parts ([web.dev optimize INP](https://web.dev/articles/optimize-inp)).
- For the grid: use 1 delegated pointer listener on the SVG, not 1 handler per tile. Do not update React state on every pointermove; use refs plus rAF. Prefer CSS `:hover` and transitions. Keep the grid a small client island. Honor `prefers-reduced-motion`.

**CLS**
- Reserve the grid's space in CSS (`aspect-ratio`, fixed grid template). Do not compute the tile count from `window` after hydration and then re-render.
- Animate only `transform` and `opacity`, because layout properties cause shifts ([web.dev optimize CLS](https://web.dev/articles/optimize-cls)).
- `next/font` adjusts fallback metrics by default (`adjustFontFallback`) ([next/font](https://nextjs.org/docs/app/api-reference/components/font)). Shifts within 500 ms of user input are not counted ([web.dev CLS](https://web.dev/articles/optimize-cls)).
- Make the server and client render the same grid. Seeded, deterministic patterns only. This also avoids the Cache Components `Math.random()` error (section 3.8).

## 5. Off-site steps, in order

1. **Deploy the MUST items first.** Check them with the command list in section 2 (M12).
2. **Google Search Console: verify.**
   - Preferred: a **Domain property `vonstorch.com`**. Add the TXT record at the **apex** in IONOS DNS. A Domain property "includes all subdomains … and multiple protocols", and it can only be verified with DNS ([add property](https://support.google.com/webmasters/answer/34592?hl=en), [verification](https://support.google.com/webmasters/answer/9008080?hl=en)). Verifying the root domain "automatically verifies ownership of all subdomains".
   - Why not a Domain property for `max.vonstorch.com`? `max` is a CNAME. A TXT record cannot exist next to a CNAME at the same name ([RFC 1034 §3.6.2](https://www.rfc-editor.org/rfc/rfc1034#section-3.6.2)). Google's own rule says: when a CNAME exists and its target is not a parent domain, use the TXT method ([verification](https://support.google.com/webmasters/answer/9008080?hl=en)). The TXT therefore goes on `vonstorch.com`.
   - Fallback, if you cannot edit the IONOS DNS: a **URL-prefix property `https://max.vonstorch.com/`** with the HTML-tag method, through `metadata.verification.google` in the root layout ([Next verification field](https://nextjs.org/docs/app/api-reference/functions/generate-metadata#verification)). ## 7. Where sources conflict

1. **Streamed metadata vs. canonical placement.** Next.js says streamed metadata in `<body>` "is interpreted correctly" by Googlebot ([Next](https://nextjs.org/docs/app/api-reference/functions/generate-metadata#streaming-metadata)). Google says `rel=canonical` "is only accepted if it appears in the `<head>`" ([Google](https://developers.google.com/search/docs/crawling-indexing/consolidate-duplicate-urls)). Resolution: keep the metadata static or prerendered, so it is in `<head>` (M4).
2. **Favicon formats.** Next.js supports `icon.svg` ([Next](https://nextjs.org/docs/app/api-reference/file-conventions/metadata/app-icons)). Google Search does not list SVG ([Google, 2026-08-28](https://developers.google.com/search/docs/appearance/favicon-in-search)). Resolution: ship ICO/PNG. An SVG can be an extra.
3. **Sitemap fields.** The Next.js examples use `lastModified: new Date()`, `changeFrequency`, and `priority` ([Next](https://nextjs.org/docs/app/api-reference/file-conventions/metadata/sitemap)). Google ignores `changefreq` and `priority`, and it distrusts inaccurate lastmod values ([Google](https://developers.google.com/search/docs/crawling-indexing/sitemaps/build-sitemap)). Resolution: use real dates only.
4. **`dynamicParams = false`.** The Next MDX guide uses it ([MDX](https://nextjs.org/docs/app/guides/mdx)). It is removed under Cache Components ([route segment config](https://nextjs.org/docs/app/api-reference/file-conventions/route-segment-config)). Resolution: `notFound()` or a `proxy` check.
5. **"One H1 per page".** SEO blogs say to put your name in an H1 ([Orbit Media](https://www.orbitmedia.com/blog/personal-seo/)). Google says heading count and order don't matter for Search ([starter guide](https://developers.google.com/search/docs/fundamentals/seo-starter-guide)), but it rewrites titles when no clear main title exists ([title links](https://developers.google.com/search/docs/appearance/title-link)). Resolution: one H1, for clarity and accessibility. It is not a ranking rule.
6. **Schema type.** Brand-focused guides suggest `Organization` schema on the home page ([Semrush, 2025-12-09](https://www.semrush.com/blog/entity-based-seo-strategy/)). Personal-brand blogs say Person schema "triggers" knowledge panels. Google: use Person for people, not Organization ([Article](https://developers.google.com/search/docs/appearance/structured-data/article)). ProfilePage is the documented container ([ProfilePage](https://developers.google.com/search/docs/appearance/structured-data/profile-page)). No markup guarantees a SERP feature.
7. **Wikidata.** Entity-SEO guides recommend a Wikidata item ([Backlinko](https://backlinko.com/entity-seo)). Wikidata requires notability, for example "serious and publicly available references" ([Wikidata:Notability](https://www.wikidata.org/wiki/Wikidata:Notability)). Resolution: do not create a self-authored item unless independent sources exist.
8. **www vs apex.** Vercel recommends `www` as the primary for apex domains ([Vercel domains](https://vercel.com/docs/domains/working-with-domains/deploying-and-redirecting)). Google: subdomain vs subdirectory does not matter for ranking, and site names and favicons work per subdomain ([starter guide](https://developers.google.com/search/docs/fundamentals/seo-starter-guide), [site names](https://developers.google.com/search/docs/appearance/site-names)). Resolution: keep `max.vonstorch.com`.
9. **IndexNow "instant indexing".** Marketing sites claim fast indexing. Google does not take part ([indexnow.org](https://www.indexnow.org/faq)).
