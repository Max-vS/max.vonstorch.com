# Forms research: React Hook Form + Zod vs. alternatives

Date: 2026-09-26. Scope: form approach for the site rewrite (Next.js 16 App Router, React 19, React Compiler, Bun, Tailwind 4, Biome, Neon + Drizzle, Better Auth, Vercel). Research only. I changed no files in the repo.

Labels: **VERIFIED** means I checked it in official docs, npm, or library source, or ran a local test. **UNVERIFIED** means I did not confirm it.

---

## 1. Decision

**Pick:** use React Hook Form **7.89.0** with Zod **4.6.5** through `@hookform/resolvers` **5.9.1**. Use it only where the site has real input fields:

- the community submit form
- the email + password login, if you keep it

Everywhere else, use no form library:

- **Admin approve/delete:** plain React 19 `<form action={serverAction.bind(null, id)}>` with a `useFormStatus` submit button.
- **GitHub sign-in:** one button that calls `authClient.signIn.social({ provider: "github" })`.

**Why, in one line:** no alternative is clearly better today, and RHF + Zod works in our exact setup. Details:

- **TanStack Form** is in the middle of a rewrite. The v2 alpha was announced on 2026-08-06 (alpha.0 on npm 2026-08-10), and it changes exactly the Server Action integration.
- **Conform's** modern API is officially "experimental and may change in minor versions".
- **RHF** is the most used and most active option:
  - 66M downloads/week, and 7.89.0 was published today.
  - It supports Zod 4 and Zod Mini.
  - Its docs now have an official "Server Actions / useActionState" section.
  - Our exact form pattern passes a runtime test with React Compiler 1.0.0 (section 7).

**Install:**

```sh
bun add react-hook-form@^7.89.0 @hookform/resolvers@^5.9.1 zod@^4.6.5
# only if the React Compiler is enabled (core decision):
bun add -D babel-plugin-react-compiler@^1.0.0   # + reactCompiler: true in next.config.ts
```

**Do not install `react-hook-form@beta` (v8) yet.** `@hookform/resolvers@5.9.1` declares the peer dependency `react-hook-form: ^7.55.0`.

- `npm install` fails with `ERESOLVE`.
- Bun prints `warn: incorrect peer dependency "react-hook-form@8.0.0-beta.4"`.
- Status: VERIFIED.

**How it fits together (details in section 5):**

1. **Shared schema.** Put one schema in `lib/marks/schema.ts`. Import Zod with `import * as z from "zod"`. Do not add `server-only`, because the client imports this module too.
2. **Client validation.** Call `useForm({ resolver: zodResolver(markSchema), defaultValues, mode: "onTouched" })`.
3. **Submit.** Call the Server Action directly: `handleSubmit(async (values) => { const r = await submitMark(values); … })`.
   - `formState.isSubmitting` is the pending state.
   - You need no `useActionState` and no `useEffect`.
4. **Server re-validation.** Run `markSchema.safeParse(input)` again on the server. On failure, return `{ status: "error", fieldErrors: z.flattenError(err).fieldErrors }`. Return `formError` for bot-check and rate-limit failures.
5. **Map server errors back.**
   - Field errors: `setError(field, { message })`.
   - Form errors and thrown errors: `setError("root.server", { message })`.
6. **After success, do not call `reset()`.** Show a thank-you state, or remount the form with a new `key`. Section 7 explains why.

## 3. What changed since 2024–2025 knowledge

### React Hook Form

- **v8 is in beta.** 8.0.0-beta.4 came out 2026-09-26. The migration guide says: "V8 adds first-class support for the React Compiler." Breaking changes:
  - `Controller` `field.ref` is now the real DOM node.
  - The `useFieldArray` `id` is renamed to `key`, and `keyName` is removed.
  - The `<Watch names>` prop is renamed to `name`.
  - The `WatchObserver` type is removed.

  None of these affect our planned code. Upgrading later is cheap.
- **7.84.0** (2026-08-01): `<Form action>` accepts a function ("Server Action style"). The component is still marked **BETA**. Section 8 explains why we do not use it.
- **7.85.0:** support for `<Activity />`.
- **7.86.0:** `getErrors`.
- **7.88.0:** `<ErrorMessage />` is now in core (`import { ErrorMessage } from "react-hook-form"`). The old `@hookform/error-message` package (2.0.1) has not changed since 2022.
- **7.79.0:** "formState.errors reactivity with React compiler" fix.
- **Official docs section**, added Aug 2026: [Server Actions / useActionState](https://react-hook-form.com/advanced-usage#ServerActionsuseActionState). **Its example has a bug:** it calls the `useActionState` dispatcher outside a transition (section 8).

### @hookform/resolvers

- **v5.0.0** (2025-04-01): infers input and output types separately. Requires RHF ≥ 7.55.
- Because of this, `useForm<T>` with a single generic conflicts when the schema uses `.default()`. Either omit the generic, or use `useForm<z.input<S>, unknown, z.output<S>>`.

### Zod 4 ([changelog](https://zod.dev/v4/changelog))

- `message` is deprecated. Use `error` instead.
- `invalid_type_error` and `required_error` are **removed**. They now cause a TypeScript error (VERIFIED: TS2769 with zod 4.6.5).
- `err.flatten()` and `err.format()` are deprecated. Use `z.flattenError(err)` and `z.treeifyError(err)` ([error formatting](https://zod.dev/error-formatting)).
- `z.string().email()` is deprecated. Use `z.email()`, `z.uuid()`, and similar top-level functions.
- `.default()` short-circuits on `undefined` and must match the **output** type.
- The input type of `z.coerce.*` is `unknown`.
- Use `z.strictObject()` / `z.looseObject()` instead of `.strict()` / `.passthrough()`.
- Zod 4.5 added `z.compile()`. Zod 4.6 added `.validate()`, `z.withParser()` (for CSP), and `@zod/mini` as a standalone package.
- **Import style matters for bundle size.** The docs use `import * as z from "zod"` ([basics](https://zod.dev/basics)). In a Next 16.3.6 Turbopack production build:

  | Import | Client JS added (gzip) |
  |---|---|
  | `import * as z from "zod"` | +40 KB |
  | `import { z } from "zod"` | +95 KB |

  Status: VERIFIED (section 4).

### React 19.x

- `ReactDOM.useFormState` is renamed to `React.useActionState`. React 19.3 still exports the old name, but it logs "ReactDOM.useFormState has been renamed to React.useActionState" (VERIFIED in the react-dom 19.3.0 dev build).
- React 19.3 ([blog](https://react.dev/blog/2026/09/09/react-19-3)):
  - `onReset` now fires when React automatically resets a form after a Server Action.
  - `submitter` is now part of submit events.
  - The `useFormStatus` reset bug is fixed.

### TanStack Form

- v1 uses Standard Schema natively. You do not need `@tanstack/zod-form-adapter`.
- `useStore` is deprecated. Use `useSelector` instead ([reactivity](https://tanstack.com/form/latest/docs/framework/react/guides/reactivity)).
- Next.js helpers live in `@tanstack/react-form-nextjs`.
- v2 is in alpha.

### Conform

- The default `@conform-to/zod` import is for Zod 3. With Zod 4, you **must** import from `@conform-to/zod/v4`. The wrong import fails with "Export named 'ZodEffects' not found".
- The future API accepts a Standard Schema directly: `useForm(schema, opts)`.

### Drizzle

- In v1, the validator packages moved into core, for example `drizzle-orm/zod`.
- `drizzle-zod` still works with 0.45.x.

### Next.js docs

- The [Forms guide](https://nextjs.org/docs/app/guides/forms) (16.3.6, updated 2026-08-25) still shows Zod 3 code: `invalid_type_error` and `error.flatten()`. **Do not copy it.** It fails type-checking with Zod 4.6.5, and at runtime the custom message is ignored (VERIFIED).

### Biome

- Biome 2.5.8+ has the nursery rule `lint/nursery/useReactCompiler`. It runs the compiler in lint mode.
- VERIFIED on 2.5.14: it flags `watch()` from `useForm()` in the host component. It does **not** flag `watch()` read from `useFormContext()` in a child, and that is the case that actually breaks.

## 4. Options compared

### Client JS cost

I measured with `next build` on Next 16.3.6 (Turbopack). The value is the gzip -9 sum of the route's client chunks, minus an empty client route (172.7 KB). Status: VERIFIED.

| Client code on the form route | Added JS (gzip) |
|---|---|
| React 19 only, Zod only on the server | **+0 KB** |
| Zod classic, `import * as z` | +40.4 KB |
| Zod classic, `import { z }` | +94.7 KB |
| zod/mini | +25.3 KB |
| RHF only (no Zod) | +11.5 KB |
| **RHF + resolvers + Zod (pick)** | **+53.0 KB** |
| RHF + resolvers + zod/mini | +37.9 KB |
| TanStack Form (`-nextjs`) + Zod | +56.4 KB |
| Conform (future API) + Zod | +52.3 KB |

Most of the cost is Zod on the client, not the form library. The three form libraries differ by only about 4 KB.

**Mitigation:** load the form chunk only when the visitor opens the "leave a mark" UI, for example with `next/dynamic` or `React.lazy` inside a client component. With esbuild instead of Turbopack, zod/mini is much smaller (6.7 KB vs 26 KB for classic). Turbopack does not tree-shake it as well.

|---|---|---|---|---|

**Why progressive enhancement does not decide the choice.** The community form cannot work without JS in any option:

- The canvas needs JS to paint.
- The bot token (Turnstile or BotID) needs JS.

The admin approve/delete forms are Server Component forms, so they get no-JS support for free. **Recommendation:** drop "works without JS" for the community form. Show a `<noscript>` note, and keep the marks wall server-rendered.

**Why not plain React 19 for everything?**

- It is the leanest option: 0 KB, and the Next.js docs use it. It is a valid choice if the user wants zero form dependencies.
- But the user asked for RHF + Zod, and RHF gives real UX benefits for about 13 KB:
  - client-side schema errors before a round trip ("Paint at least one tile", empty note)
  - "touched" logic
  - focus on the first invalid field
  - no React auto-reset problem
- Plain `<form action>` has an auto-reset problem: React 19 **clears uncontrolled inputs even when the action returns validation errors**. VERIFIED: the input value was `""` after a returned error. Every field must then be controlled, or restored from the returned state.

## 5. Community form: the pick, in code

Status of the three files below:

- runtime-tested with and without React Compiler 1.0.0 (section 7)

The source is in the scratchpad (section 12).

### `lib/marks/schema.ts` (shared by client and server)

```ts
// Shared by the client form (zodResolver) and the Server Action (safeParse).
// No "use server" / "server-only" here: this module must be importable on both sides.
import * as z from "zod";

export const NAME_MAX = 40;
export const NOTE_MAX = 140;
export const TILE_COUNT = 150;
export const PALETTE_SIZE = 8; // tile value 0 = empty, 1..PALETTE_SIZE = paint (placeholder encoding)
export const GROUNDS = ["paper", "ink"] as const;

export const markSchema = z.object({
  // Optional for the visitor, but kept as a string ('' = anonymous) so input type === output type.
  name: z.string().trim().max(NAME_MAX, `Keep it under ${NAME_MAX} characters`),
  note: z
    .string()
    .trim()
    .min(1, "Write a short note")
    .max(NOTE_MAX, `Keep it under ${NOTE_MAX} characters`),
  tiles: z
    .array(z.int().min(0).max(PALETTE_SIZE))
    .length(TILE_COUNT)
    .refine((tiles) => tiles.some((tile) => tile !== 0), "Paint at least one tile"),
  ground: z.enum(GROUNDS),
  // Bot-protection token (e.g. Turnstile). Drop this field if the check is header-based (Vercel BotID).
  token: z.string().min(1, "Wait for the bot check to finish"),
});

export type MarkValues = z.input<typeof markSchema>;
export type MarkFieldErrors = { [K in keyof MarkValues]?: string[] };

export type SubmitMarkResult =
  | { status: "success" }
  | { status: "error"; fieldErrors?: MarkFieldErrors; formError?: string };
```

Notes on the schema:

- **Tile encoding and `ground` are placeholders.** Align them with the data agent's column type. For example, `smallint[]` or `jsonb` with `$type<number[]>()`.
- **Keep `name` as a string.** Map `''` to `null` on insert. Then `z.input` equals `z.output`, and `useForm` needs no explicit generics.
- **Counting characters.**
  - `.max()`, HTML `maxLength`, and `note.length` all count UTF-16 code units, so they agree. An emoji counts as 2.
  - Grapheme counting (`Intl.Segmenter`) would need the same custom check on the client and the server. Not worth it.

### `app/(site)/community/actions.ts`

```ts
"use server";

import * as z from "zod";
import { type MarkValues, markSchema, type SubmitMarkResult } from "@/lib/marks/schema";

// verifyBotToken / allowSubmission / insertPendingMark are owned by other research areas.

// The parameter type is for DX only. Server Actions are public POST endpoints:
// everything is re-validated here.
export async function submitMark(input: MarkValues): Promise<SubmitMarkResult> {
  const parsed = markSchema.safeParse(input);
  if (!parsed.success) {
    return { status: "error", fieldErrors: z.flattenError(parsed.error).fieldErrors };
  }

  const { name, note, tiles, ground, token } = parsed.data;

  if (!(await verifyBotToken(token))) {
    return { status: "error", formError: "The bot check failed. Reload the page and try again." };
  }
  if (!(await allowSubmission())) {
    return { status: "error", formError: "Too many marks from your network. Try again later." };
  }

  await insertPendingMark({ name: name || null, note, tiles, ground });
  return { status: "success" };
}
```

About this action:

- **Why re-validate?** Next.js 16 docs: "Server Functions are reachable via direct POST requests, not just through your application's UI." ([mutating data](https://nextjs.org/docs/app/getting-started/mutating-data))
- **Expected failures:** return an error state. Do not throw.
- **Unexpected throws** (for example, the DB is down): the client `try/catch` below shows a generic message.
- **No `revalidatePath` on submit.** The mark is still pending. Revalidate on approve.

### `components/community/mark-form.tsx`

```tsx
"use client";

import { zodResolver } from "@hookform/resolvers/zod";
import { useState } from "react";
import { Controller, useForm, useWatch } from "react-hook-form";
import { submitMark } from "@/app/(site)/community/actions";
import {
  GROUNDS, type MarkValues, markSchema, NAME_MAX, NOTE_MAX, type SubmitMarkResult, TILE_COUNT,
} from "@/lib/marks/schema";
import { BotCheck } from "./bot-check";
import { TileCanvas } from "./tile-canvas";

const defaultValues: MarkValues = {
  name: "",
  note: "",
  tiles: Array<number>(TILE_COUNT).fill(0),
  ground: "paper",
  token: "",
};

export function MarkForm() {
  const [sent, setSent] = useState(false);
  const {
    control,
    register,
    handleSubmit,
    setError,
    setValue,
    formState: { errors, isSubmitting, isSubmitted }, // read formState HERE, not via context
  } = useForm({
    resolver: zodResolver(markSchema),
    defaultValues,
    mode: "onTouched",
  });

  // React Compiler: use useWatch, never watch().
  const note = useWatch({ control, name: "note" });
  const ground = useWatch({ control, name: "ground" });

  const onSubmit = handleSubmit(async (values) => {
    let result: SubmitMarkResult;
    try {
      result = await submitMark(values); // values = Zod output (trimmed)
    } catch {
      setError("root.server", { message: "Could not reach the server. Try again." });
      return;
    }
    if (result.status === "success") {
      setSent(true); // swap the UI instead of reset()
      return;
    }
    for (const [field, messages] of Object.entries(result.fieldErrors ?? {})) {
      const message = messages?.[0];
      if (message) setError(field as keyof MarkValues, { message });
    }
    if (result.formError) setError("root.server", { message: result.formError });
  });

  if (sent) {
    return <p role="status">Thanks! Your mark shows up after a quick review.</p>;
  }

  return (
    <form onSubmit={onSubmit} noValidate>
      {/* Custom canvas as a controlled RHF value. The canvas keeps the in-progress stroke
          locally and calls onChange once per stroke (pointerup), not per pointermove. */}
      <Controller
        control={control}
        name="tiles"
        render={({ field }) => (
          <TileCanvas tiles={field.value} onChange={field.onChange} ground={ground} />
        )}
      />
      {errors.tiles?.message && <p>{errors.tiles.message}</p>}

      {/* Radio-style buttons without a UI library: real radios + Tailwind 4 `has-checked:`.
          Brush shape/colour are painting tools: plain useState radios, NOT registered. */}
      <fieldset>
        <legend>Ground</legend>
        {GROUNDS.map((value) => (
          <label key={value} className="has-checked:ring-2">
            <input type="radio" value={value} className="sr-only" {...register("ground")} />
            {value}
          </label>
        ))}
      </fieldset>

      <label htmlFor="mark-name">Name (optional)</label>
      <input id="mark-name" maxLength={NAME_MAX} autoComplete="nickname"
        aria-invalid={errors.name ? true : undefined} {...register("name")} />
      {errors.name && <p>{errors.name.message}</p>}

      <label htmlFor="mark-note">Note</label>
      <textarea id="mark-note" rows={3} maxLength={NOTE_MAX}
        aria-invalid={errors.note ? true : undefined} aria-describedby="mark-note-left"
        {...register("note")} />
      <p id="mark-note-left">{NOTE_MAX - note.length} characters left</p>
      {errors.note && <p>{errors.note.message}</p>}

      {/* Turnstile-style widget: token arrives async via callback. */}
      <BotCheck onToken={(token) => setValue("token", token, { shouldValidate: isSubmitted })} />
      {errors.token && <p>{errors.token.message}</p>}
      {errors.root?.server && <p role="alert">{errors.root.server.message}</p>}

      <button type="submit" disabled={isSubmitting}>
        {isSubmitting ? "Sending…" : "Leave your mark"}
      </button>
    </form>
  );
}
```

**Why call the action directly, and not through `useActionState`?**

- The server result comes back typed, inside the submit handler. We map it with `setError` right away, so we need no `useEffect` to sync state.
- `isSubmitting` already covers the pending UI.
- There is no React form auto-reset, because we do not use the `action` prop.
- Next.js docs show Server Functions called from event handlers without a transition.
- `useActionState` would only help with no-JS support, and that is not possible for this form.

**Bot token field.** Keep the field only if the check is token-based (Turnstile). With Vercel BotID:

- `initBotId({ protect: [{ path, method: "POST" }] })` runs in `instrumentation-client.ts`.
- `checkBotId()` runs in the Server Action.
- So there is no token field.

Status: UNVERIFIED in detail; this is outside my scope.

**Live counter accessibility.** Do not make the counter `aria-live` on every keystroke. If you want announcements, announce only when fewer than about 20 characters are left.

```ts
import { auth } from "@/lib/auth";

const markId = z.uuid();

async function requireOwner() {
  const session = await auth.api.getSession({ headers: await headers() });
  if (!session) throw new Error("Unauthorized"); // + owner allowlist check (auth agent)
}

// Bound args come from the client: authorize AND validate in every action.
export async function approveMark(id: string) {
  await requireOwner();
  await setMarkStatus(markId.parse(id), "approved");
  revalidatePath("/"); // or updateTag(...) if the data agent uses cache tags
}

export async function deleteMark(id: string) {
  await requireOwner();
  await removeMark(markId.parse(id));
  revalidatePath("/admin");
}
```

**Optional polish:** use `useOptimistic` in a client list to hide the row at once. This is the pattern from the Next.js Forms guide.

### Email + password (only if you keep it)

Use the same RHF pattern:

```tsx
const signInSchema = z.object({ email: z.email("Enter an email"), password: z.string().min(1, "Enter your password") });
const { register, handleSubmit, setError, formState: { errors, isSubmitting } } =
  useForm({ resolver: zodResolver(signInSchema), defaultValues: { email: "", password: "" } });
```

## 7. React Compiler and RHF: test results

**Test setup:**

- **Libraries:** React 19.3.0, react-dom client.
- **DOM:** happy-dom 20.14.5 under `bun test` 1.3.11.
- **Compiler:** components compiled with `babel-plugin-react-compiler@1.0.0` (Babel 7.29.7, `target: "19"`), and also run uncompiled.

**Results:**

| Pattern | RHF 7.89.0 compiled | RHF 8.0.0-beta.4 compiled | Uncompiled (both) |
|---|---|---|---|
| **Our `MarkForm`:** `useWatch` counter, zodResolver errors, `Controller` canvas, `setValue` token, server `setError` mapping, thrown-error fallback, `isSubmitting` label, values kept after a server error, success state | **PASS** | **PASS** | PASS |
| `watch()` from `useForm()` in the host component | PASS (the compiler **skips** the component: "Use of incompatible library") | PASS (skipped) | PASS |
| `useFormContext().watch()` in a child | **FAIL** (stale: 140 instead of 135) | **FAIL** | PASS |
| `useWatch({ name })` in a child | PASS | PASS | PASS |
| `useFormContext().formState.errors` in a child | **FAIL** (error never shows) | **FAIL** | PASS |
| `useFormState()` in a child | PASS | PASS | PASS |
| `register()` + `reset()`, then type and submit | **FAIL** (submitted `""`, input lost) | PASS (fixed in v8) | PASS |

This matches the community report of 2026-05-06 in [RHF discussion #12524](https://github.com/orgs/react-hook-form/discussions/12524). It also matches the compiler's built-in list in [DefaultModuleTypeProvider.ts](https://github.com/react/react/blob/main/compiler/packages/babel-plugin-react-compiler/src/HIR/DefaultModuleTypeProvider.ts), which says: "Only the `watch()` function returned by react-hook-form's `useForm()` API is incompatible".

### Project rules (put these in the coding guidelines)

1. **Never use `watch()`.** Use `useWatch({ control, name })` instead ([React docs: incompatible-library](https://react.dev/reference/eslint-plugin-react-hooks/lints/incompatible-library)).
2. **Read `formState` only in the component that calls `useForm`.** Children use `useFormState({ control })` or the new `<ErrorMessage>`.
3. **Avoid `reset()` with `register`ed inputs.** After success, swap the UI or remount with a new `key`. For programmatic value rewrites, use `<Controller>`.
4. **Use `'use no memo'` only as a temporary escape hatch.**
5. **Optional:** enable `"nursery": { "useReactCompiler": "error" }` in `biome.json`. It catches rule 1 in the host component only, not the context cases.

## 8. Integration guides read, per pair (with conflicts)

### RHF + Zod ([resolvers README](https://github.com/react-hook-form/resolvers#zod))

- Zod 4 and Zod Mini are supported since 5.1.0. VERIFIED at runtime: `zodResolver` works with a `zod/mini` schema and with a classic schema, and the submit handler gets trimmed output.
- `standardSchemaResolver` also works, but its errors have `type: ""` instead of Zod's issue code.

### RHF + Server Actions / `useActionState`

Source: [RHF advanced usage, "Server Actions / useActionState"](https://react-hook-form.com/advanced-usage#ServerActionsuseActionState).

- **Conflict (VERIFIED).** The docs example is `onSubmit={handleSubmit((data) => submitAction(data))}`. It triggers the React 19.3 dev error "An async function with useActionState was called outside of a transition", and `isPending` never becomes `true`.
- **Fix:** `handleSubmit((data) => startTransition(() => submitAction(data)))`. VERIFIED: the pending label shows, and there is no error.
- The docs also map `state.fieldErrors` with a `useEffect` + `setError`.
- Our direct-call pattern avoids both problems.

### RHF `<Form action={fn}>` (7.84+, BETA)

Source: [RHF Form docs](https://react-hook-form.com/docs/useform/form). I read the `src/form.tsx` source (VERIFIED). The component:

- calls `await action(formData)` with FormData rebuilt from RHF values
- **ignores the return value**
- does not run inside a transition
- shows only *thrown* errors, as `errors.root.server`

So it cannot carry server field errors, and it is not a fit for `useActionState`. Do not use it here.

### TanStack Form + Next.js + Zod

Sources: [SSR / Next.js guide](https://tanstack.com/form/latest/docs/framework/react/guides/ssr) and [validation](https://tanstack.com/form/latest/docs/framework/react/guides/validation).

- **Pattern:** shared `formOptions`, then `createServerValidate` + `ServerValidateError` in the action, then `useActionState(someAction, initialFormState)` + `useTransform(form => mergeForm(form, state!), [state])`, then `<form action={action as never} onSubmit={() => form.handleSubmit()}>`.
- **Import pitfall:** server code must import from `@tanstack/react-form-nextjs`. Otherwise you get the "needs useState" error.
- **Docs mismatch:** the guide says "Install `@tanstack/react-form`", but the code imports `-nextjs`.
- **Typing friction:** in my build, a form-level Zod validator gave `field.state.meta.errors` items of type `unknown`. I needed a cast for `.message` (TS2339, observed).
- **v2 will replace this server flow.** Source: [v2 alpha blog](https://tanstack.com/blog/announcing-tanstack-form-v2-alpha).

### Conform + Next.js + Zod 4

Sources: [Next.js guide](https://conform.guide/integration/nextjs), [parseWithZod](https://conform.guide/api/zod/parseWithZod), [future useForm](https://github.com/edmundhung/conform/blob/main/docs/api/react/future/useForm.md), [discussion #954](https://github.com/edmundhung/conform/discussions/954).

- **Conflict (VERIFIED):** the guide uses `useFormState` from `react-dom`, which React 19 renamed. It also imports `@conform-to/zod`, which is the Zod 3 entry.
- The maintainer recommends "locking your version range to patch" when you use the future APIs.

### React 19 native + Zod (no library)

Sources: [Next.js Forms guide](https://nextjs.org/docs/app/guides/forms), [useActionState](https://react.dev/reference/react/useActionState), [`<form>`](https://react.dev/reference/react-dom/components/form).

- **Conflicts:** the Next.js snippet uses the Zod 3 API (section 3). React also auto-resets uncontrolled fields after a returned error (VERIFIED).
- A type-checked baseline sketch is in `sizecheck/sketch/baseline/`:
  - a `(prevState, formData)` action
  - JSON tiles in a hidden input
  - the submitted values returned for `defaultValue`

### Next.js + React Compiler ([reactCompiler](https://nextjs.org/docs/app/api-reference/config/next-config-js/reactCompiler))

- Opt-in: `reactCompiler: true`, plus `babel-plugin-react-compiler`.
- Next runs the compiler through Babel, but only on relevant files (SWC optimization).
- `compilationMode: "annotation"` is available, and so is `'use no memo'`.

### Better Auth + forms

- Server Actions: need `nextCookies()`, as the last plugin.
- The session check in an action: `auth.api.getSession({ headers: await headers() })`.

## 9. drizzle-zod / `drizzle-orm/zod`: worth it?

**Verdict:** not for the form schema. You may use it server-side only.

**What I tested (VERIFIED)** with `pgTable("marks", { name: varchar({length: 40}), note: varchar({length: 140}).notNull(), tiles: jsonb().$type<number[]>(), ground: pgEnum(...) … })`, using both `drizzle-zod@0.8.3` (with drizzle-orm 0.45.3) and `drizzle-orm@1.0.0-rc.4` / `drizzle-orm/zod`:

- **Good:** the varchar lengths become `.max(40)` / `.max(140)`, and pgEnum becomes `z.enum`.
- **Needs overrides:** `jsonb` columns must be overridden, because `$type` is not used for validation. Nullable columns accept `null`. Columns with defaults become optional.
- **Messages are generic** ("Too big: expected string to have <=140 characters"), so you would override the form messages anyway.
- **You still need extras:** `.pick()` for the columns, and `.extend()` for `token`.

**The deciding problem is the client bundle.** Both packages do `import { z } from "zod/v4"`. That form defeats tree-shaking, and it also pulls `drizzle-orm/pg-core` into the client. Measured with esbuild: the table + `createInsertSchema` is **~100 KB gzip with Zod**, and +10–12 KB without Zod. The form schema also risks importing server modules if the table file imports the DB client.

**Better approach:**

- Share the limit constants (`NAME_MAX`, `NOTE_MAX`, `TILE_COUNT`, `GROUNDS`) between the Drizzle table (`varchar({ length: NOTE_MAX })`, `pgEnum("ground", GROUNDS)`) and the hand-written Zod schema. That keeps DB and form in sync with zero extra dependencies.
- Use `createSelectSchema` / `createInsertSchema` only in server code, if at all. Pick the import path from the Drizzle version the data agent chooses:
  - `drizzle-zod` for 0.45.x
  - `drizzle-orm/zod` for v1 RC

## 10. Gotchas

1. **Import Zod as `import * as z from "zod"`, never `import { z } from "zod"`.** Measured: +40 KB vs +95 KB gzip client JS in Next 16.3.6 / Turbopack. Biome's `performance/noNamespaceImport` would forbid the namespace import. It is not in the recommended set, so do not enable it.
2. **The Next.js Forms guide Zod code is Zod 3.** Use the `error` param and `z.flattenError()` instead.
3. **RHF v8 beta and `@hookform/resolvers` 5.9.1 conflict on peer dependencies.** Stay on 7.89.
4. **React Compiler rules** (section 7): use `useWatch`, read `formState` in the host or with `useFormState`, and do not combine `register` with `reset()`.
5. **React 19 `<form action>` auto-resets uncontrolled fields after every completed action**, including ones that return errors. The RHF `onSubmit` pattern avoids this. React 19.3 now fires `onReset` when this happens.
6. **The RHF docs' `useActionState` example needs `startTransition`** (section 8).
7. **RHF `<Form action={fn}>` drops the action's return value.** Do not use it for server field errors.
8. **`useForm<T>` with a single generic plus `zodResolver` breaks when the schema has `.default()`.** Omit the generic, or pass all three. Our schema has no defaults.
9. **Keep the canvas out of per-pointermove RHF updates.** Commit on pointerup through `field.onChange`.
10. **Do not import drizzle-derived schemas into client components** (section 9).
11. **Server Actions are public endpoints.** Validate, rate-limit, and bot-check in `submitMark`. Authorize and validate bound ids in the admin actions.
12. **Strict CSP.** Zod probes `new Function` for its JIT, and a strict CSP reports the probe as a violation, which adds noise to CSP reports. If you add a strict CSP with reporting, set `z.config({ jitless: true })`. Zod falls back automatically either way. VERIFIED in the source, `v4/core/util.js`.
13. **TanStack Form docs** use `action={action as never}`, and `useStore` is deprecated. This is noted only if TanStack is reconsidered after v2 is stable.

## 11. Open risks / UNVERIFIED

- **RHF v8 stable** has no release date. v8 "first-class React Compiler support" is **partial** in my test: context `watch()` and `formState` are still stale.
- **TanStack Form and Conform** were not tested at runtime under the React Compiler.
- **Turbopack vs esbuild tree-shaking.** zod/mini is much smaller in esbuild than in Turbopack (6.7 KB vs 25 KB). I did not investigate why (the locales may not be removed).
- **Next.js calling a Server Action from `handleSubmit` outside a transition.** This is allowed per the docs (event-handler example), and my test used a mocked action, not Next's real `callServer`. Next.js behavior for `redirect()` inside such a call is not tested. `submitMark` does not redirect.
- **Bot protection choice** (Turnstile token vs Vercel BotID headers) changes the schema (`token` field). This is for the other agent's scope.
- **Bundle numbers** are gzip -9 sums of route chunks. Real transfer uses Brotli. Treat the deltas as relative.
