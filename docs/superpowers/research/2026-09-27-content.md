# MDX content for Next.js 16 — research report

Date: 2026-09-26. Scope: MDX articles for `/writing` + `/writing/[slug]`, external-only posts, code blocks, images, RSS, sitemap.
Method: npm registry (`npm view`), GitHub API (source, releases, changelogs, tests), official docs (read at the exact release tag where possible), and **local builds** of 5 candidate setups on Next.js 16.3.6 + Turbopack with Bun (scratch dir `research/tmp/content/exp-*`).
Legend: ✅ tested by a local build · 📄 from official docs/source only · ⚠️ gotcha · UNVERIFIED = could not confirm.

---

## 0. TL;DR

**Pick: official `@next/mdx` + Turbopack `import.meta.glob` + `remark-frontmatter`/`remark-mdx-frontmatter` + Zod 4, `@shikijs/rehype` for code, `rehype-mdx-import-media` + `next/image` for images, `@tailwindcss/typography` for prose. No content layer, no codegen.** ✅ (built, dev-HMR tested, Biome-clean, TS 7 typecheck passes)

Why: it is the Next.js-documented path; MDX files become real modules in the Turbopack graph (imports of components and images work, HMR works, new files appear without restart); it adds zero generated folders, zero watcher processes, zero tsconfig aliases; frontmatter is validated with Zod at build time and the build fails with a clear message. Next.js 16.3 added `import.meta.glob`, which removes the only reason people reached for Contentlayer/Velite/Content Collections on small blogs: listing all posts.

Three things that shape the setup (all verified):
1. **Turbopack needs plugin names as strings + JSON-serializable options** in `createMDX()`. Passing a function throws `...mdx-js-loader.js ... does not have serializable options`.
2. **Next.js 16.3.6 bug:** `import.meta.glob('../…')` and `import.meta.glob('/…')` silently return `{}`. Fixed on canary only (PR #96557, merged 2026-09-10, not in 16.3.6). Workaround: put the glob in a module *inside* `content/` and use `./` patterns.
3. **Cache Components** (if the core stack enables `cacheComponents: true`) forbids `export const dynamicParams` and `export const dynamic` (build error). Remove both; pages and feed still prerender (tested).

Verdicts:
- **@next/mdx + glob** — sweet spot for "few posts, custom layout": fewest moving parts, official, bundler-native.
- **Content Collections** — best "content layer" DX (typed `allPosts`, transforms, Standard Schema), but its MDX package is stale and it adds 4 touch points + codegen. Pick it only if you need transforms/relations across many collections.
- **Fumadocs MDX** — most active and batteries included (GFM, Shiki, TOC, heading ids by default; macro API with no config file), but it is a docs framework core (`fumadocs-core` required, ESM config, docs-oriented output such as `icon` attributes on `<pre>`). Overkill for a personal blog; good fallback if TOC/search are wanted later.
- **Velite** — skip for now: stable line vendors Zod 3, 1.0 is alpha, Next integration is a documented hack, `sharp` dependency (their docs mention `free(): invalid size` crashes on Vercel; not tested).
- **next-mdx-remote-client** — right tool for MDX from a CMS/DB (remote content). For local files it re-implements what the bundler already does.
- **next-mdx-remote** — do not use (archived; CVE-2026-0969). Note: Vercel's "Portfolio Starter Kit" (linked from the Next.js MDX guide) still uses it.

## 4. Conflicts between guides (flagged)

1. **Listing posts:** Next MDX guide says use `fs`/`globby` (+ `gray-matter`); the Next 16.3 blog positions `import.meta.glob` for "blog posts" (its sample even uses `gray-matter` on `.md` + a custom loader). → Use the glob with `remark-mdx-frontmatter` (no fs, HMR-aware, no unmaintained gray-matter).
2. **`pageExtensions`:** Next MDX guide tells you to add `md`/`mdx` and says this "allows .mdx files to act as pages, routes, or imports". It is only needed for `page.mdx` routes; imports work without it (✅ tested). Leaving it out avoids stray `.md` routes.
3. **Plugin syntax:** the guide's main example imports plugin functions; since Turbopack is the default in 16, only the string form (its sub-section) works.
4. **Install list:** Next docs install 4 packages (`@next/mdx @mdx-js/loader @mdx-js/react @types/mdx`); the `@next/mdx` README's App Router section says only `npm install @next/mdx`. Both are wrong for App Router + Turbopack: `@mdx-js/loader` is required (the Turbopack rule runs `mdx-js-loader.js`, which `require`s it), while `@mdx-js/react` is **not** needed when `mdx-components.tsx` exists (✅ fresh install + build without it passes). The docs page is shared with the Pages Router, where `@mdx-js/react` provides the `MDXProvider` context. Bun does **not** auto-install these optional peers (✅ fresh `bun add @next/mdx` → no `@mdx-js/*`). → Install `@next/mdx @mdx-js/loader @types/mdx`; add `@mdx-js/react` only if you ever use `MDXProvider`.
5. **Example code:** the guide's "complete working example" (Vercel Portfolio Starter Kit, `vercel/examples/solutions/blog`) uses archived `next-mdx-remote`, `tailwindcss 4.0.0-alpha.13`, `sugar-high ^0.6` and builds RSS without XML escaping. The official `create-next-app --example mdx` is on React 18 / TS 4.9. Treat both as outdated.
6. **Images:** Next guide maps `img` → `next/image` with `sizes`/`style` for all images; `rehype-mdx-import-media` README maps `img: Image` directly. Both break for remote images of unknown size → conditional component.
7. **Config format:** Fumadocs recommends `next.config.mjs` (ESM, native TS resolver for `.ts`); Velite's Turbopack recipe needs top-level await (ESM). The pick works with the default `next.config.ts`.
8. **Route-segment config vs Cache Components:** docs recommend `dynamicParams=false` and `dynamic='force-static'`; both are build errors with `cacheComponents: true` (✅ error text: `Route segment config "dynamicParams" is not compatible with nextConfig.cacheComponents. Please remove it.`).

## 6. Recommended setup (verified end-to-end)

### Install (Bun)
```bash
bun add @next/mdx @mdx-js/loader remark-gfm remark-frontmatter remark-mdx-frontmatter @shikijs/rehype rehype-mdx-import-media zod
bun add -d @types/mdx @tailwindcss/typography
```
(`@mdx-js/react` from the Next docs install line is omitted on purpose: App Router takes components from `mdx-components.tsx`; ✅ fresh build without it passes. See §4.4.)
Verified versions: `@next/mdx@16.3.6` (keep equal to `next`), `@mdx-js/loader@3.1.1`, `remark-gfm@4.0.1`, `remark-frontmatter@5.0.0`, `remark-mdx-frontmatter@6.0.0`, `@shikijs/rehype@4.4.3`, `rehype-mdx-import-media@1.4.0`, `zod@4.6.5`, `@types/mdx@2.0.14`, `@tailwindcss/typography@0.5.20`. Requires `next ≥ 16.3` (glob) and Node ≥ 22 (remark-mdx-frontmatter 6); Vercel default is 24.x (Node 20 deprecated 2026-10-01) → optionally `"engines": { "node": "24.x" }`.

### File layout

Route groups ✅ tested: `/writing` renders with the tiles layout, `/writing/[slug]` with the reading layout, feed outside both.

### next.config.ts
```ts
import createMDX from "@next/mdx";
import type { NextConfig } from "next";

const nextConfig: NextConfig = {};

// Turbopack: plugin names as strings, options must be JSON-serializable.
const withMDX = createMDX({
  options: {
    remarkPlugins: ["remark-gfm", "remark-frontmatter", "remark-mdx-frontmatter"],
    rehypePlugins: [
      [
        "@shikijs/rehype",
        { themes: { light: "github-light", dark: "github-dark" }, defaultColor: "light-dark()" },
      ],
      "rehype-mdx-import-media", // keep last
    ],
  },
});

export default withMDX(nextConfig);
```
Need function options later (e.g. Shiki `transformers` for `// [!code highlight]`)? Put them in a local plugin and pass its absolute path (✅ tested):
```ts
// mdx/rehype-code.mjs
import rehypeShiki from "@shikijs/rehype";
import { transformerNotationHighlight } from "@shikijs/transformers";
export default function rehypeCode() {
  return rehypeShiki.call(this, {
    themes: { light: "github-light", dark: "github-dark" },
    transformers: [transformerNotationHighlight()],
  });
}
// next.config.ts
rehypePlugins: [fileURLToPath(new URL("./mdx/rehype-code.mjs", import.meta.url)), "rehype-mdx-import-media"]
```
(Alternative with serializable meta-string features: `['rehype-pretty-code', {theme:{light,dark}, keepBackground:false}]` ✅ — then write the dual-theme CSS yourself.)

### mdx-components.tsx
```tsx
import type { MDXComponents } from "mdx/types";
import Image, { type StaticImageData } from "next/image";
import type { ComponentProps } from "react";

type ImgProps = Omit<ComponentProps<"img">, "src"> & { src?: string | StaticImageData };

const components = {
  // rehype-mdx-import-media turns relative image paths into imports (StaticImageData).
  img: ({ src, alt = "", ...props }: ImgProps) =>
    typeof src === "object" ? (
      <Image src={src} alt={alt} sizes="(min-width: 768px) 65ch, 100vw" />
    ) : (
      // biome-ignore lint/performance/noImgElement: remote images without known size
      <img src={src} alt={alt} {...props} />
    ),
```

### content/writing.ts
```ts
import type { MDXContent } from "mdx/types";
import { z } from "zod";

const frontmatterSchema = z.strictObject({
  title: z.string().min(1),
  date: z.iso.date(),
  summary: z.string().min(1),
  // Set only for posts that live on another site (Substack, LinkedIn, ...).
  url: z.httpUrl().optional(),
});

export type Post = z.infer<typeof frontmatterSchema> & { slug: string; href: string; external: boolean };

// Turbopack-only API (Next.js 16.3+). Patterns must be string literals.
// Next.js <= 16.3.6: patterns starting with ../ or / silently match nothing (fixed on canary, #96557).
const frontmatters = import.meta.glob("./writing/*.mdx", { eager: true, import: "frontmatter" });
const bodies = import.meta.glob("./writing/*.mdx", { import: "default" });

const slugOf = (path: string) => path.slice(path.lastIndexOf("/") + 1, -".mdx".length);

export const posts: Post[] = Object.entries(frontmatters)
  .map(([path, data]) => {
    const result = frontmatterSchema.safeParse(data);
    if (!result.success) {
      throw new Error(`Invalid frontmatter in ${path}:\n${z.prettifyError(result.error)}`);
    }
    const slug = slugOf(path);
    const external = result.data.url !== undefined;
    return { ...result.data, slug, external, href: result.data.url ?? `/writing/${slug}` };
  })
  .sort((a, b) => b.date.localeCompare(a.date));

export const localPosts = posts.filter((post) => !post.external);

export function getPost(slug: string) {
  return localPosts.find((post) => post.slug === slug);
}

export async function getPostBody(slug: string) {
  const load = bodies[`./writing/${slug}.mdx`];
  return load ? ((await load()) as MDXContent) : undefined;
}
```

```ts
import { posts } from "@/content/writing";

export const dynamic = "force-static"; // remove if cacheComponents: true

const baseUrl = "https://max.vonstorch.com";

const escapeXml = (value: string) => value.replace(/[<>&'"]/g, (c) => `&#${c.charCodeAt(0)};`);

export function GET() {
  const items = posts
    .map((post) => {
      const link = post.external ? post.href : `${baseUrl}${post.href}`;
      return `<item><title>${escapeXml(post.title)}</title><link>${escapeXml(link)}</link><guid>${escapeXml(link)}</guid><description>${escapeXml(post.summary)}</description><pubDate>${new Date(post.date).toUTCString()}</pubDate></item>`;
    })
    .join("");

  return new Response(
    `<?xml version="1.0" encoding="UTF-8"?><rss version="2.0" xmlns:atom="http://www.w3.org/2005/Atom"><channel><title>Writing</title><link>${baseUrl}/writing</link><description>Writing</description><atom:link href="${baseUrl}/writing/feed.xml" rel="self" type="application/rss+xml"/>${items}</channel></rss>`,
    { headers: { "Content-Type": "application/rss+xml; charset=utf-8" } },
  );
}
```

## 7. Gotchas (all ✅ reproduced unless marked)

- `import.meta.glob('../content/writing/*.mdx')` → `{}` on 16.3.6 with **no error**; `/writing` renders an empty list and `generateStaticParams` returns `[]`. Glob from inside `content/` (`./writing/*.mdx`). After a release containing #96557, `lib/posts.ts` with `../` will work (keys stay origin-relative; with `base` they become base-relative) — slug from basename keeps code stable either way.
- `import.meta.glob` = Turbopack only. `next build --webpack` breaks it (📄).
- Function-valued MDX plugin options → build error `loader …/@next/mdx/mdx-js-loader.js for match "{*,next-mdx-rule}" does not have serializable options`.
- Missing `mdx-components.tsx` → `TypeError: b.default.createContext is not a function`.
- Route handlers are dynamic by default → feed needs `dynamic = "force-static"` (non-Cache-Components) to be static.
- Cache Components: remove `dynamicParams`/`dynamic`; `generateStaticParams` must return ≥ 1 → if the site starts with **only external posts**, the build fails (📄 docs: empty array = build error). Write one local post first, or keep Cache Components off.
- `z.strictObject` rejects unknown frontmatter keys (catches typos like `sumary`); switch to `z.object` if you want freedom.
- MDX 3 is stricter than Markdown: raw `<` / `{` in prose, HTML comments `<!-- -->` (use `{/* */}`) and `<https://autolinks>` fail the build (📄 MDX behavior, not re-tested here).
- Shiki `light-dark()` only follows the OS if `color-scheme` is set; with a class-based toggle set `color-scheme: dark` on `<html class="dark">`. `light-dark()` needs modern browsers (Baseline 2024).
- Tailwind scans `.mdx`, so words like `flex` in prose may emit CSS (harmless). Classes used inside MDX JSX work ✅.
- Biome ignores `.mdx`; in lint-staged/lefthook use `biome check --no-errors-on-unmatched …` or an MDX-only commit fails.
- `@mdx-js/loader` and `@mdx-js/react` are *optional* peers of `@next/mdx`; Bun does not install them for you. Forgetting `@mdx-js/loader` breaks the build; `@mdx-js/react` is unused in App Router.
- `gray-matter` (still named in Next docs) is unmaintained (js-yaml 3) — https://github.com/sdorra/content-collections/issues/798; if you ever need it, use `@11ty/gray-matter`.
- MDX is executable code: never compile MDX from untrusted sources (CVE-2026-0969 context). Local-author content is fine.

## 8. Changes / deprecations vs 2024–2025 knowledge

- `next-mdx-remote`: **archived**, CVE-2026-0969 (GHSA-g4xw-jxrg-5f6m, CVSS 8.8, 4.3.0–<6.0.0); v6 blocks JS expressions by default (`blockJS`, `blockDangerousJS`). Successor for remote MDX: `next-mdx-remote-client`.
- Next 16: Turbopack default for dev **and** build; 16.3 adds `import.meta.glob`, build FS cache on by default, TS 7 typecheck support, `catchError` boundaries, root params, Instant Navigations (opt-in `cacheComponents` + `partialPrefetching`).
- `@next/mdx`: string plugin names (since late 2024) are now the *only* option under the default bundler; `extension` regex works with Turbopack (2025); `useMDXComponents()` takes **no argument** anymore (docs changed 2025-07, #80871); `experimental.mdxRs` still "not recommended for production".
- Shiki 4 (drops Node 18, removes deprecated APIs such as `getHighlighter` → `createHighlighter`); `light-dark()` default color mode.
- Zod 4: `z.iso.date()`, `z.httpUrl()`, `z.url()` top-level; `z.string().url()/.email()/.date()` deprecated; `z.prettifyError`.
- Content Collections: `schema: (z) => …` removed (0.12) → Standard Schema object; implicit `content` property deprecated (add `content: z.string()`); `defineConfig({ collections })` → `{ content }` (0.14); `gray-matter` → `@11ty/gray-matter` (0.15.3); singletons (0.14).
- Velite: Turbopack broke the webpack plugin → config-file hack; 1.0 alpha in progress.
- Fumadocs MDX 15: ESM-only `next.config`, macro API (no `source.config.ts` needed), Standard Schema, requires `fumadocs-core ≥ 16.7`.
- `remark-mdx-images` deprecated → `rehype-mdx-import-media`.
- `remark-mdx-frontmatter` 6: Node ≥ 22.
- `@tailwindcss/typography`: configured with `@plugin` in CSS (TW v4), not `tailwind.config.js`.
- `feed` 6: ESM, Node ≥ 20.
- Biome 2.5: still no Markdown/MDX. Side note for tooling: Biome 2.5 deprecates `linter.rules.recommended: true` → `"preset": "recommended"` (`biome migrate --write`); the `create-next-app@16.3.6` `--biome` template still emits the deprecated form.
- TypeScript 7.0.2 (native) is latest; this setup typechecks with it ✅.
