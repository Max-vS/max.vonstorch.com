## 2. Biome

### 2.1 Changes since 2.3.10 that matter here (VERIFIED: blog posts + CHANGELOG + tests)

- **2.5: `linter.rules.recommended` is deprecated. Use `linter.rules.preset`** (`"recommended" | "all" | "none"`).
  `biome migrate --write` does it. Old key still works in 2.5.14 but prints a DEPRECATED info.
  Source: https://biomejs.dev/blog/biome-v2-5/ and https://biomejs.dev/reference/configuration/#linterrulespreset
- **2.5: Biome lints and formats `.svg` files.** Test result: a fresh create-next-app scaffold gets **5 errors**
  (`a11y/noSvgWithoutTitle` on `public/*.svg`). This repo gets **3 errors** (`public/favicon.svg`,
  `public/logo-lime.svg`, `public/logo-molten.svg`). Fix: exclude `public/**/*.svg` (section 7.1).
- 2.5: `--watch` for `check/lint/format`; `--reporter concise` (short output for coding agents); LSP go-to-definition
  (`biome.gotoDefinition`); ~13% faster lint; `delimiterSpacing` formatter option; 73 rules promoted.
- 2.5 promoted `a11y/noAmbiguousAnchorText` to **recommended**. Test: `<a href="/writing">link</a>` = error.
- 2.5.x: new nursery rules `useTailwindShorthandClasses` (`w-4 h-4` -> `size-4`), `noTailwindArbitraryValue`,
  `noTailwindRawColors` (all in a new **tailwind domain**, all nursery, so off by default); `useReactCompiler`
  (nursery, 2.5.8, React Compiler lint mode); `noUnusedClasses` / `noUndeclaredClasses` (CSS <-> JSX, project domain).
- 2.4: **`noDuplicateClasses` assist action** (removes duplicate classes in `class`/`className` and in `clsx`/`cn`/`cva`
  calls). Off by default. Test: it finds duplicates inside `cn("flex p-4 flex")` with no extra options.
- 2.4: editor `biome.lsp.inlineConfig`; `--profile-rules`; SARIF + multiple reporters; `types` domain.
- 2.4-2.5 Tailwind parser fixes: `@utility` names with `/`, digits, functional names (`px-*`); container-query
  variants; `@variant` with `@xl`; `!important` marker; many dashed utilities.
- Tailwind side: Tailwind 4.2.0 "Allow escape characters in `@utility` names to improve support with formatters such
  as Biome" — the only Tailwind <-> Biome cross-reference found.

### 2.5 Biome + Tailwind v4 (VERIFIED by tests on 2.5.14)

- `css.parser.tailwindDirectives: true` is required. With it, Biome parses and formats: `@import "tailwindcss"`,
  `@theme` / `@theme inline`, `@plugin`, `@source` / `@source not` / `@source inline("tile-{1..9}")`,
  `@custom-variant`, `@utility` (incl. `@keyframes` inside `@theme`), `@apply` with variants, `@variant` blocks,
  `@reference`, `--theme()`, `--spacing()`, `--alpha()`. Without it: parse errors.
- The repo's `"suspicious": { "noUnknownAtRules": "off" }` is **not needed**. Test: repo `globals.css` +
  `@plugin/@custom-variant/@utility` gives 0 diagnostics on both 2.3.10 and 2.5.14 without the override.
- `useSortedClasses` (source at tag `@biomejs/biome@2.5.14`):
  - Group **nursery**, not recommended, fix kind **Unsafe** (so not applied on save unless you set `"fix": "safe"`).
  - Docs: "work in progress ... only partially implemented"; "Only the default Tailwind CSS configuration is
    supported"; no custom utilities/variants; sort config is hard-coded. A `sort_v4.rs` engine exists in the crate
    but the rule does not use it yet (rule still builds `SortConfig` from the old preset).
  - **Options default: no functions.** Test: with `"useSortedClasses": "on"` only `className="..."` is sorted;
    `clsx(...)` and `cn(...)` are not. You must set `"functions": ["cn", "clsx"]`. (The docs example list
    `["clsx","cva","tw","tw.*"]` is an example, not the default.)
  - Default severity when "on" = info.
  - Order differs from the official Tailwind order in some cases (test, same input):
    - Biome:    `@container inset-shadow-sm grid size-(--tile) bg-(--color-molten) text-shadow-lg not-hover:opacity-50 starting:opacity-0 data-[state=open]:bg-red-500 max-lg:hidden sm:flex lg:grid-cols-3`
    - Prettier: `@container grid size-(--tile) bg-(--color-molten) inset-shadow-sm text-shadow-lg not-hover:opacity-50 data-[state=open]:bg-red-500 max-lg:hidden sm:flex lg:grid-cols-3 starting:opacity-0`
    - Custom `@utility tile-size`: Biome puts it first (unknown class); Prettier knows it (reads the stylesheet).
  - Conclusion: consistent order, not the exact official order. Expect a one-time re-sort when Biome wires the v4 engine.
- `noDuplicateClasses` assist: works in `cn()` by default. Editor code action: `source.action.noDuplicateClasses.biome`.

### 2.6 Biome + Bun (VERIFIED)

- Install: `bun add -D -E @biomejs/biome@2.5.14` (Biome docs: `-E` pins; "why pinning the version is important").
- Run: Biome docs use `bunx --bun @biomejs/biome <cmd>`; `bunx biome` resolves the local binary (test printed 2.5.14).
  `@biomejs/biome` has no install scripts (binary comes from optional `@biomejs/cli-*` packages), so Bun's
  script-blocking does not affect it.
- Lockfile: `bun.lock` is **not** in Biome's "protected files" list (`composer.lock, npm-shrinkwrap.json,
  package-lock.json, yarn.lock`). Biome skips it as an unknown `.lock` file; with `files.ignoreUnknown: true` it is silent.
- `bun add` keeps the existing `package.json` indent (tested with tabs), so Biome and Bun do not fight.
- `biome ci`: no `--write`; GitHub annotations; uses `--changed` with VCS. GitHub Action:
  `biomejs/setup-biome@v2` (reads the version from the bun lockfile) then `biome ci`. Vercel builds do not lint.
- `biome check`/`ci` fail on errors only; infos (unsorted classes) do not fail.

### 3.3 CSS-first config and next/font (VERIFIED, both guides agree)

- Next.js font docs ("With Tailwind CSS"): set `variable: '--font-inter'` on the font, put `inter.variable` on
  `<html>`, then `@theme inline { --font-sans: var(--font-inter); }`.
- Tailwind theme docs: "When defining theme variables that reference other variables, use the `inline` option".
  Without `inline`, the variable resolves where it is defined and can fall back to the wrong font.
- `@theme` = tokens that create utilities. `:root` = plain variables with no utilities (Tailwind docs). So: brand
  colors in `@theme`; runtime `--tile` on `:root`/inline style, used as `size-(--tile)`.
- `next/font/google` exports `Familjen_Grotesk` (400-700, variable) and `JetBrains_Mono` (100-800, variable).
- Automatic source detection scans the whole project except `.gitignore`d files, `node_modules`, binaries, CSS
  files, lockfiles. MDX in the repo is scanned. No `@source` needed.

### 3.4 Prose for MDX (VERIFIED)

- Next.js MDX guide still says: use `@tailwindcss/typography` with a shared layout and `prose` classes.
  https://nextjs.org/docs/app/guides/mdx#using-tailwind-typography-plugin
- README (v4): `npm install -D @tailwindcss/typography`, then `@plugin "@tailwindcss/typography";` in CSS.
  Colors: `@utility prose-xyz { --tw-prose-body: ...; --tw-prose-headings: ...; }`.
  Rename: `@plugin "@tailwindcss/typography" { className: wysiwyg; }`.
  Deep CSS changes still need `@config "./tailwind.config.js"` (JS theme API) — avoid unless needed.
- `tailwindcss.com/docs/typography-plugin` now redirects (307) to the GitHub repo.

### 3.5 Is prettier-plugin-tailwindcss still needed with Biome? **No.**

- It is the only sorter that reads the v4 stylesheet (`tailwindStylesheet` option is required for v4) and matches
  Tailwind's order exactly. But it is a Prettier plugin; Prettier must format the file. Running Prettier and Biome
  as formatters on the same TSX files makes two formatters fight.
- Biome `useSortedClasses` gives a stable order in one tool. Class order does not change the CSS output.
- 0.8.0 exports `prettier-plugin-tailwindcss/sorter` (`createSorter`) for other tools; nothing uses it with Biome yet.
- Tailwind IntelliSense has a manual "Tailwind CSS: Sort Selection" (pre-release) command.

### 3.6 Other Tailwind integrations (not recommended now)

- `@tailwindcss/webpack` (4.2): Tailwind blog claims 2.17x faster than PostCSS on tailwindcss.com (Next.js/Turbopack).
- `@tailwindcss/turbopack` (npm 4.3.3, 2026-07-31; CHANGELOG "Unreleased"): README config
  `turbopack: { rules: { '*.css': { loaders: ['@tailwindcss/turbopack'], as: '*.css' } } }`.
  Neither guide uses it. UNVERIFIED with Next 16.3.6 (not tested). Re-check at Tailwind 4.4.

## 4. `cn` helper (VERIFIED)

- Old standard (still valid): `twMerge(clsx(inputs))`. clsx 2.1.1 (2024), tailwind-merge 3.7.0 (v4.0-v4.3 support).
  tailwind-merge needs config only for custom non-color theme keys (e.g. `--text-hero`, `--spacing-gutter`);
  custom `--color-*` works out of the box.
- **New (Sept 2026): shadcn moved the helper into the `cn` package.** shadcn changelog 2026-09-03:
  "`npx shadcn init` installs `cn` and generates a one-line `lib/utils.ts`" = `export { cn } from "cn"`.
  `npx shadcn@latest migrate cn` rewrites existing projects. README: drop-in for `clsx` + `tailwind-merge`, "same output
  as tailwind-merge for every input", 356,000 differential tests, zero deps, ~26 KB min, `cn/config` has
  `createCn/extendTailwindMerge`, `cn/lite`, optional `cn build` (Vite plugin / `withCn` Next wrapper). Node >= 20.
- Spot test (6 inputs incl. v4.2/4.3 utilities `inset-s-*`, `pbs-*`, `scrollbar-*`, `zoom-*`, `@container-size`,
  `size-(--tile)`, custom utility): **identical** output to `twMerge(clsx())`.
- Pick `cn` 0.4.0 because the originator of the pattern made it the default and it cuts one dependency.
  Fallback is a one-file change. Risk: 0.x, 3 weeks old.
- cva / tailwind-variants: not needed (no variant-heavy component library planned).

## 5. Editor setup (VS Code / Cursor) (VERIFIED)

- Biome ext (`biomejs.biome`, VS Code Marketplace; Open VSX for Cursor). Docs: format on save =
  `editor.formatOnSave: true`; fix on save = `"source.fixAll.biome": "explicit"` (safe fixes only); imports =
  `"source.organizeImports.biome": "explicit"`; other assist actions = `source.action.<name>.biome`.
  Binary lookup: `biome.lsp.bin` -> `node_modules` -> PATH. Renamed: `biome.lspBin` -> `biome.lsp.bin`,
  `biome.requireConfigFile` -> `biome.requireConfiguration`.
- The extension registers for language IDs incl. **`tailwindcss`**, `css`, `xml` (source: `biome-vscode/src/constants.ts`).
- Tailwind IntelliSense README recommends `"files.associations": { "*.css": "tailwindcss" }` and
  `"editor.quickSuggestions": { "strings": "on" }`; `tailwindCSS.classFunctions` enables completions inside `cn()`.
  With the association, add `"[tailwindcss]": { "editor.defaultFormatter": "biomejs.biome" }`.
- Keep per-language `[typescriptreact]` etc. blocks: VS Code docs: "Language-specific editor settings always override
  non-language-specific editor settings ... language-specific user settings override non-language-specific workspace
  settings." A user-level Prettier default would otherwise win.
- Biome does not support Markdown/MDX (roadmap 2026: no owner). `.mdx` files are skipped (`ignoreUnknown`).
  Use the MDX extension for syntax. Do not add Prettier for `.mdx`: Prettier supports MDX 1 only
  (prettier/prettier#12209 "MDX 3" is OPEN, checked 2026-09-26). Leave `.mdx` unformatted.

## 9. Where guides conflict

1. Packages: Tailwind guide installs `postcss` too; Next.js docs and CNA do not. `@tailwindcss/postcss@4.3.3`
   already depends on `postcss ^8.5.16`. Follow Next.js/CNA.
2. Linter: Tailwind guide scaffolds with `--eslint`. Next.js offers `--biome`. Use Biome.
3. `$schema`: Biome docs prefer `./node_modules/@biomejs/biome/configuration_schema.json`; CNA writes a versioned URL (stale).
4. Ignores: CNA uses `!.next`; Biome docs recommend `!!` for output folders.
5. `rules.recommended` (CNA) is deprecated in Biome 2.5 (`preset`).
6. Biome version: CNA 16.3.6 pins 2.4.2; latest 2.5.14.
7. VS Code: Tailwind IntelliSense wants `*.css` in `tailwindcss` mode; Biome docs do not mention it. Add a
   `[tailwindcss]` formatter block (supported by the Biome extension).
8. Sorting: Tailwind docs point to the Prettier plugin; Biome has its own nursery rule. Orders differ (tested). Use one.
9. Biome's lefthook recipe uses `npx @biomejs/biome`; with Bun use `bunx biome`.
10. `useSortedClasses` docs show a function list that looks like a default; the real default sorts no functions (tested).
11. Biome config reference says `css.formatter.enabled` default `false`; 2.5.14 formats CSS by default (observed).
12. Tailwind blog: webpack/turbopack loaders are faster; both install guides still use PostCSS.

## 10. Deprecations vs 2024-2025 knowledge

- Biome 2.5: `linter.rules.recommended` -> `linter.rules.preset`. (Biome 2.0, 2025: `files.ignore/include` ->
  `files.includes`; top-level `organizeImports` -> `assist.actions.source.organizeImports`.)
- Biome ext 3.x: `biome.lspBin` -> `biome.lsp.bin`; `biome.requireConfigFile` -> `biome.requireConfiguration`.
- Biome 2.5 now lints `.svg`; `noAmbiguousAnchorText` recommended.
- Next.js 16: `next lint` removed; `eslint` key in `next.config` removed; build does not lint.
- Tailwind 4.2: `start-*`/`end-*` deprecated. IntelliSense 0.16 marks `@variant` for defining variants as
  deprecated (use `@custom-variant`). 4.3.3 changed default font stacks. JS `tailwind.config.js` only via `@config`.
- shadcn: `cn` helper moved to the `cn` package (Sept 2026).
- prettier-plugin-tailwindcss 0.8: Prettier >= 3.7; v4 needs `tailwindStylesheet`.
- lefthook 2.0: `exclude` regex removed, `skip_output` removed, CLI flags renamed.
- Tailwind Plus: closed to new customers (Shopify, 2026-09-09).

- `@tailwindcss/turbopack` may become the recommended Next.js path in Tailwind 4.4. UNVERIFIED (not tested).
- Tailwind tooling roadmap after the Shopify move is not stated.
