## 1. Decisions (sweet spot)

| Topic | Pick | One-line reason |
|---|---|---|
| ORM version | `drizzle-orm@1.0.0-rc.4` + `drizzle-kit@1.0.0-rc.4`, pinned exact (`bun add -E`) | Drizzle docs install `@rc` on every get-started/connect page; v1 layout (migrations v3, relations v2, `drizzle-orm/zod`) avoids a later forced upgrade. Fallback: 0.45.3 / 0.31.11. |
| Driver on Vercel | `pg` (node-postgres) `Pool` + `drizzle-orm/node-postgres` + `attachDatabasePool` (`@vercel/functions`), pooled `DATABASE_URL` | Neon and Vercel both recommend TCP pooling on Fluid compute; interactive transactions work; same driver for app, drizzle-kit, local and tests. |
| Neon serverless driver | Not needed | Only for Edge/non-Fluid runtimes. |
| Validation | `drizzle-orm/zod` (built into v1) + `zod@4.6.5` | `drizzle-zod` is frozen ("all new updates go to Drizzle ORM directly"). |
| Provisioning | `vercel integration add neon` with explicit flags (no Neon Auth, no Development env) + dashboard toggle for preview branching | CLI is scriptable; defaults add Neon Auth and connect Development to the production branch. |
| Migrations | `drizzle-kit generate` locally (commit SQL) + `drizzle-kit migrate` in the Vercel build, before `next build` | Neon's Vercel docs say "run migrations in build step"; each preview branch and prod get the same SQL; no `push` on shared DBs. |
| Env loading for drizzle-kit | `@next/env` `loadEnvConfig()` in `drizzle.config.ts`; drop `dotenv` | Next.js docs recommend it for ORM config files; drizzle-kit runs on Node, so Bun auto-loading does not apply (tested). |
| Rate limit | SQL count per `ip_hash` in last hour (+ global pending cap) in the Server Action | No extra service; exact 1-hour window; testable; indexed; optional Vercel WAF rule as outer shield. |
| Local dev DB | One persistent Neon `dev` branch (child of `main`), creds in `.env.development.local` | Same engine/version as prod, zero local infra. Offline alternative: `pglite-server` (no Docker). |
| Tests | PGlite in-process, apply the real `drizzle/` migrations | Fast, no Docker, no Neon quota; verified. |

## 3. Drizzle v1 status and what changed (vs 2024–2025 knowledge)

Status: v1.0 is **RC, not stable**. `npm latest` = 0.45.3. No official v1 GA date (open issue #5660; asks for down-migrations, RLS).
But every Drizzle get-started/connect page now installs `drizzle-orm@rc` / `drizzle-kit@rc`
(e.g. https://orm.drizzle.team/docs/pg/connect-neon, shared `InstallPackages.mdx`). Docs moved to dialect paths (`/docs/pg/...`).

Upgrade guide: https://orm.drizzle.team/docs/upgrade-v1 · changes: https://orm.drizzle.team/docs/pg/v0-v1-changes ·
relations: https://orm.drizzle.team/docs/pg/relations-v1-v2 · releases: https://github.com/drizzle-team/drizzle-orm/releases

Breaking / relevant changes in v1:
- **Migrations folder v3**: no `meta/_journal.json`; one folder per migration: `drizzle/<YYYYMMDDHHMMSS>_<name>/migration.sql` + `snapshot.json`
  (verified). Convert old folders with `drizzle-kit up`. `drizzle-kit drop` removed.
  0.31.11 still writes `drizzle/0000_init.sql` + `drizzle/meta/0000_snapshot.json` + `drizzle/meta/_journal.json` (verified).
- Migration table `drizzle.__drizzle_migrations` gets `name` and `applied_at` (auto-upgraded); migrator now applies **every missing**
  migration (matched by folder name), not only newer timestamps.
- **Relational Queries v1 removed** (`relations()`, `db._query`) → `defineRelations()` (RQB v2).
- Casing API: `drizzle({ casing })` replaced by `snakeCase.table(...)` / `camelCase.table(...)` (rc.1 breaking). Explicit column
  names (`timestamp("created_at")`) work in both 0.45 and v1 — use them to stay version-neutral.
- Validators consolidated: `drizzle-zod` → `drizzle-orm/zod` (also valibot, typebox, arktype, effect-schema).
- `getTableColumns` → `getColumns`; `.array().array()` → `.array('[][]')`; `.enableRLS()` → `pgTable.withRLS()`;
  `.generatedAlwaysAs()` only accepts SQL.
- `drizzle-kit push`/`pull` manage **all schemas by default** (`schemaFilter` default `["*"]`) — see gotcha G3.
- `push --strict` removed (prompts are default); new `push --explain` (dry run); `--force` auto-accepts data loss.
- New: `drizzle-kit check` commutativity check across git branches; `--output json`; programmatic SDK `drizzle-kit/cli`;
  `drizzle-kit mcp`; `drizzle-kit skills`; top-level await in config; JIT mappers (`jit: true`); codecs; SQL comments.
- neon-http driver still has **no interactive transactions** in rc.4 (`throw new Error("No transactions support in neon-http driver")`,
  verified in package source); `db.batch()` only.

Recommendation: pin `1.0.0-rc.4` exactly for both packages; this app uses only stable surfaces (pgTable, select/insert/update/delete,
migrations). Re-test before each RC bump. If an RC blocks you: `drizzle-orm@0.45.3`, `drizzle-kit@0.31.11`, `drizzle-zod@0.8.3`
(later upgrade = `drizzle-kit up`).

## 4. Driver choice on Vercel Fluid compute

| Option | Transport | Transactions | Fit on Vercel Fluid |
|---|---|---|---|
| `drizzle-orm/neon-http` + `neon()` | HTTP fetch per query | No `db.transaction()`; `db.batch()` = non-interactive tx | "Classic serverless"/Edge. Lowest first-query cost, no reuse. |
| `drizzle-orm/neon-serverless` + `Pool` (WebSocket) | WebSocket | Yes | For Edge/Workers needing tx; WS must not outlive a request there. |
| **`drizzle-orm/node-postgres` + `pg.Pool` + `attachDatabasePool`** | TCP (TLS) | **Yes** | **Recommended by Neon and Vercel for Fluid.** Connection reused across requests in a warm instance. |

Sources:
- Neon "Choosing your connection method": Vercel (Fluid) → `pg` with `@vercel/functions` — https://neon.com/docs/connect/choose-connection
- Neon "Connecting to Neon from Vercel": "With Vercel Fluid, we recommend a standard Postgres TCP connection … and a connection pool",
  full Drizzle + `attachDatabasePool` example — https://neon.com/docs/guides/vercel-connection-methods
- Vercel KB "Connection Pooling with Vercel Functions" (updated 2026-07-23): global pool + `attachDatabasePool`, idle timeout ~5 s,
  do not set max pool size 1 — https://vercel.com/kb/guide/connection-pooling-with-functions
- `attachDatabasePool` reference — https://vercel.com/docs/functions/functions-api-reference/vercel-functions-package
- Neon agent skill `neon-postgres` (plugin 2.0.1): "On Vercel, use node-postgres … with `attachDatabasePool`".

How `attachDatabasePool` works (read in @vercel/functions 3.9.9 source): on every pg `release` event it calls `waitUntil` for
`idleTimeoutMillis + 100 ms` so idle clients close before the instance suspends. It returns early when `VERCEL_URL`/`VERCEL_REGION`
are unset → **no-op locally and during builds**. pg default `idleTimeoutMillis` is 10 000 → set 5 000 (Vercel advice) to keep the
post-response wait short. Verify Fluid is ON for this older project (default only for projects created after 2025-04-23;
dashboard toggle or `"fluid": true`) — https://vercel.com/docs/fluid-compute

Pooled vs direct: app uses `DATABASE_URL` (host has `-pooler`, PgBouncer transaction mode, 10 000 client conns; protocol-level
prepared statements OK; no `SET`/session state). drizzle-kit uses `DATABASE_URL_UNPOOLED` (direct) —
https://neon.com/docs/connect/connection-pooling

Transactions ("approve = update in a transaction?"): **No transaction needed.** Approve is one atomic statement:
`UPDATE marks SET status='approved', approved_at=now() WHERE id=$1 AND status='pending' RETURNING id` (idempotent; second call
returns no row — verified). Delete is one `DELETE`. Use `db.transaction()` only for multi-statement invariants later (works with pg;
verified incl. `pg_advisory_xact_lock`). Known open bug #6241/#6341: pooled `transaction()` leaks a pool client if `BEGIN` itself
fails (0.45.x and rc.4) → prefer single-statement writes.

## 5. Neon + Vercel Marketplace integration

Guides: overview https://neon.com/docs/guides/vercel-overview · Vercel-managed https://neon.com/docs/guides/vercel-managed-integration ·
Neon-managed https://neon.com/docs/guides/neon-managed-vercel-integration · cleanup https://neon.com/docs/guides/vercel-branch-cleanup ·
Vercel CLI https://vercel.com/docs/cli/integration · deployment actions https://vercel.com/docs/integrations/create-integration/deployment-integration-action

Two Marketplace paths:
- **Vercel-managed (Native Integration)** = `vercel integration add neon`. Billing in Vercel. Org "Vercel: <team>". Neon CLI needs an
  **API key** (`neon login` does not work). Legacy Admin/Member roles. Settings (plan, compute size, scale-to-zero) only in Vercel dashboard.
- **Neon-managed (Connectable Account)**: existing Neon account, billing in Neon; optional persistent `vercel-dev` branch for the
  Development env; preview-branch cleanup on git-branch deletion. Dashboard-only setup.

Env vars injected (Vercel-managed): `DATABASE_URL` (pooled), `DATABASE_URL_UNPOOLED` (direct), `PGHOST`, `PGHOST_UNPOOLED`, `PGUSER`,
`PGDATABASE`, `PGPASSWORD`, legacy `POSTGRES_URL`, `POSTGRES_URL_NON_POOLING`, `POSTGRES_USER`, `POSTGRES_HOST`, `POSTGRES_PASSWORD`,
`POSTGRES_DATABASE`, `POSTGRES_URL_NO_SSL`, `POSTGRES_PRISMA_URL`; plus `NEON_AUTH_BASE_URL`, `VITE_NEON_AUTH_URL` when Neon Auth is on.
Optional `--prefix`.

Preview branching (per deployment):
1. Enable in dashboard: Storage → database → Connect Project → Advanced → Deployments Configuration → **Preview**, and
   **"Resource must be active before deployment"**. (No CLI flag found in `vercel integration add --help`, CLI 60.1.3.)
2. Push to a git branch → Vercel webhook → Neon creates branch `preview/<git-branch>` (copy-on-write of the default branch).
3. Vercel **blocks the build** until the action completes, then injects branch-specific env vars for that deployment only
   (not visible in project env settings). So `drizzle-kit migrate` in the build hits the preview branch.
4. Cleanup (Vercel-managed): only when the branch's last deployment is deleted. Retention: Hobby 30 days for previews; Pro 180 days.
   Exceptions keep deployments alive (last 10 deployments, **last 20 ready previews**, open-PR head) → on a low-traffic repo preview
   branches may **never** be deleted. Neon recommends a GitHub Action on PR close (`neondatabase/delete-branch-action@v3`).
   Branches older than 14 days and inactive for 24 h get archived, but still count toward the branch limit.

`vercel integration add neon --help` (CLI 60.1.3) facts: metadata `region` ∈ {cle1, iad1, pdx1, fra1, lhr1, syd1, sin1, gru1};
metadata **`auth` (Neon Auth) default `true`**; plans `free_v3`, `launch_v3`, `scale_v3`; `-e/--environment` defaults to production,
preview and development; after provisioning it connects the project and runs `vercel env pull` (→ `.env.local`) unless `--no-env-pull`.
Since 2026-08-06 it also installs the provider's agent skills from skills.sh (https://vercel.com/changelog/vercel-marketplace-agent-skills;
exact file paths UNVERIFIED — review `git status` after).

## 8. Code (validated in the prototype; paths adapted to this repo's `lib/`)

### drizzle.config.ts
```ts
import { loadEnvConfig } from "@next/env";
import { defineConfig } from "drizzle-kit";

// drizzle-kit runs on Node and reads no .env files. Mirror Next.js: .env.development.local > .env.local > …
// On Vercel no files exist, so platform env vars are used. Existing process env always wins.
loadEnvConfig(process.cwd(), process.env.NODE_ENV !== "production");

export default defineConfig({
  dialect: "postgresql",
  schema: "./lib/db/schema.ts",
  out: "./drizzle",
  dbCredentials: { url: process.env.DATABASE_URL_UNPOOLED! }, // direct (non -pooler) URL
  schemaFilter: ["public"], // v1 default is all schemas → would try to drop neon_auth etc.
});
```
Verified: `generate`/`check` run without a URL; `migrate` fails fast with "url: undefined" when unset.

### lib/db/index.ts
```ts
import "server-only";
import { attachDatabasePool } from "@vercel/functions";
import { drizzle, type NodePgDatabase } from "drizzle-orm/node-postgres";
import { Pool } from "pg";

type Db = NodePgDatabase & { $client: Pool };
const globalForDb = globalThis as unknown as { db?: Db };

// Plain lazy getter (no Proxy): module import never touches env, so `next build` is safe without DATABASE_URL.
export function getDb(): Db {
  if (globalForDb.db) return globalForDb.db;
  const url = process.env.DATABASE_URL; // pooled
  if (!url) throw new Error("DATABASE_URL is not set");
  const pool = new Pool({ connectionString: url, idleTimeoutMillis: 5_000 });
  pool.on("error", (err) => console.error("pg pool error", err));
  attachDatabasePool(pool); // no-op outside Vercel runtime
  globalForDb.db = drizzle({ client: pool }); // v1: add `relations` here when RQB v2 is used
  return globalForDb.db;
}
```
Optional hardening: rewrite `sslmode=require` → `sslmode=verify-full` before `new Pool` (see gotcha G8). `pg` is in Next.js's default
`serverExternalPackages`, so no bundler config is needed.

### lib/db/schema.ts
```ts
import { sql } from "drizzle-orm";
import { check, index, jsonb, pgEnum, pgTable, text, timestamp, uuid, varchar } from "drizzle-orm/pg-core";

export type Tile = { shape: number; rotation: 0 | 90 | 180 | 270; fg: number; bg: number };

// Generic name so comments can reuse it later.
export const moderationStatus = pgEnum("moderation_status", ["pending", "approved"]);

export const marks = pgTable(
  "marks",
  {
    id: uuid("id").primaryKey().defaultRandom(), // not guessable; PG18-only uuidv7() avoided (Neon version may be 17)
    name: varchar("name", { length: 40 }),
    note: varchar("note", { length: 140 }),
    tiles: jsonb("tiles").$type<Tile[]>().notNull(),
    status: moderationStatus("status").notNull().default("pending"),
    createdAt: timestamp("created_at", { withTimezone: true }).notNull().defaultNow(),
    approvedAt: timestamp("approved_at", { withTimezone: true }),
    ipHash: text("ip_hash"), // HMAC-SHA256(IP_HASH_SECRET, ip), base64url; null it after 24 h
  },
  (t) => [
    // .nullsFirst() → plain "DESC", which matches orderBy(desc(...)); bare .desc() emits DESC NULLS LAST (gotcha G1)
    index("marks_feed_idx")
      .on(t.approvedAt.desc().nullsFirst(), t.id.desc().nullsFirst())
      .where(sql`${t.status} = 'approved'`),
    index("marks_queue_idx").on(t.createdAt).where(sql`${t.status} = 'pending'`),
    index("marks_rate_idx").on(t.ipHash, t.createdAt),
    check("marks_tiles_array", sql`jsonb_typeof(${t.tiles}) = 'array' and jsonb_array_length(${t.tiles}) between 1 and 256`),
    check("marks_approved_at_status", sql`(${t.status} = 'approved') = (${t.approvedAt} is not null)`),
  ],
);
```
Generated SQL (drizzle-kit 1.0.0-rc.4, verified):
```sql
CREATE TYPE "moderation_status" AS ENUM('pending', 'approved');
CREATE TABLE "marks" (
  "id" uuid PRIMARY KEY DEFAULT gen_random_uuid(),
  "name" varchar(40), "note" varchar(140), "tiles" jsonb NOT NULL,
  "status" "moderation_status" DEFAULT 'pending'::"moderation_status" NOT NULL,
  "created_at" timestamp with time zone DEFAULT now() NOT NULL,
  "approved_at" timestamp with time zone, "ip_hash" text,
  CONSTRAINT "marks_tiles_array" CHECK (jsonb_typeof("tiles") = 'array' and jsonb_array_length("tiles") between 1 and 256),
  CONSTRAINT "marks_approved_at_status" CHECK (("status" = 'approved') = ("approved_at" is not null))
);
CREATE INDEX "marks_feed_idx" ON "marks" ("approved_at" DESC,"id" DESC) WHERE "status" = 'approved';
CREATE INDEX "marks_queue_idx" ON "marks" ("created_at") WHERE "status" = 'pending';
CREATE INDEX "marks_rate_idx" ON "marks" ("ip_hash","created_at");
```

### lib/db/marks.ts (query layer, driver-agnostic so tests can pass a PGlite db)
```ts
import { and, count, desc, eq, gt, lt, or, sql } from "drizzle-orm";
import type { PgAsyncDatabase, PgQueryResultHKT } from "drizzle-orm/pg-core"; // 0.45: PgDatabase
import { createInsertSchema } from "drizzle-orm/zod";                       // 0.45: from "drizzle-zod"
import { z } from "zod";
import { marks } from "./schema";

export type AnyDb = PgAsyncDatabase<PgQueryResultHKT>;

const tile = z.object({
  shape: z.number().int().min(0).max(15),
  rotation: z.union([z.literal(0), z.literal(90), z.literal(180), z.literal(270)]),
  fg: z.number().int().min(0).max(31),
  bg: z.number().int().min(0).max(31),
});
// varchar(40)/(140) lengths are inferred as .max() (verified: 41-char name rejected)
export const newMarkSchema = createInsertSchema(marks, {
  name: (s) => s.trim().min(1),
  note: (s) => s.trim().min(1),
  tiles: z.array(tile).min(100).max(150),
}).pick({ name: true, note: true, tiles: true });

const MAX_PER_HOUR = 3;
const MAX_PENDING = 500; // global queue cap vs distributed spam

export async function insertMarkRateLimited(db: AnyDb, input: z.infer<typeof newMarkSchema>, ipHash: string) {
  const [mine] = await db.select({ n: count() }).from(marks)
    .where(and(eq(marks.ipHash, ipHash), gt(marks.createdAt, sql`now() - interval '1 hour'`)));
  if ((mine?.n ?? 0) >= MAX_PER_HOUR) return { ok: false as const, reason: "rate_limited" as const };
  const [queue] = await db.select({ n: count() }).from(marks).where(eq(marks.status, "pending"));
  if ((queue?.n ?? 0) >= MAX_PENDING) return { ok: false as const, reason: "queue_full" as const };
  const [row] = await db.insert(marks).values({ ...input, ipHash }).returning({ id: marks.id, createdAt: marks.createdAt });
  return { ok: true as const, mark: row! };
}

export async function approveMark(db: AnyDb, id: string) {
  const [row] = await db.update(marks)
    .set({ status: "approved", approvedAt: sql`now()` })
    .where(and(eq(marks.id, id), eq(marks.status, "pending")))
    .returning({ id: marks.id });
  return row ?? null;
}

export async function deleteMark(db: AnyDb, id: string) {
  await db.delete(marks).where(eq(marks.id, id));
}

// Keyset pagination, newest approval first. Never select ip_hash for public DTOs.
export async function listApprovedMarks(db: AnyDb, cursor?: { approvedAt: Date; id: string }, limit = 24) {
  return db.select({ id: marks.id, name: marks.name, note: marks.note, tiles: marks.tiles, approvedAt: marks.approvedAt })
    .from(marks)
    .where(and(eq(marks.status, "approved"), cursor
      ? or(lt(marks.approvedAt, cursor.approvedAt), and(eq(marks.approvedAt, cursor.approvedAt), lt(marks.id, cursor.id)))
      : undefined))
    .orderBy(desc(marks.approvedAt), desc(marks.id))
    .limit(limit);
}
```

### Server Action sketch (Next.js 16)
```ts
"use server";
import { createHmac } from "node:crypto";
import { updateTag } from "next/cache";
import { headers } from "next/headers";
import { getDb } from "@/lib/db";
import { approveMark, insertMarkRateLimited, newMarkSchema } from "@/lib/db/marks";

export async function submitMark(input: unknown) {
  const parsed = newMarkSchema.safeParse(input);
  if (!parsed.success) return { ok: false, reason: "invalid" } as const;
  // Vercel overwrites x-forwarded-for (anti-spoofing) → first entry is the client IP.
  const ip = (await headers()).get("x-forwarded-for")?.split(",")[0]?.trim() || "unknown";
  const ipHash = createHmac("sha256", process.env.IP_HASH_SECRET!).update(ip).digest("base64url");
  return insertMarkRateLimited(getDb(), parsed.data, ipHash); // pending → no cache invalidation needed
}

export async function approve(id: string) {
  // …admin auth check (other scope)…
  await approveMark(getDb(), id);
  updateTag("marks"); // read-your-own-writes; revalidateTag(tag) with one arg is deprecated in Next 16
}
```

DB is hit only after approve/delete (§11 cost math). Docs: https://nextjs.org/docs/app/api-reference/functions/updateTag ,
https://nextjs.org/docs/app/api-reference/functions/revalidateTag , https://nextjs.org/docs/app/api-reference/functions/cacheTag ,

## 9. Env loading with Bun (tested, Bun 1.3.11 and 1.4.2)

Bun docs: Bun auto-loads `.env`, `.env.{NODE_ENV}`, `.env.local`, `.env.{NODE_ENV}.local` **only for processes Bun runs**, and
"when invoked as `node` (via `bun --bun`, `bunx --bun`) Bun disables automatic `.env` loading" — https://bun.com/docs/runtime/environment-variables

| Command | Sees `.env.local`/`.env.development.local`? |
|---|---|
| `bun run <script>` where script runs `node …` or `drizzle-kit …` | No (1.3.11 and 1.4.2) |
| `bunx drizzle-kit …` / `bun x drizzle-kit …` | No |
| `bun run --bun drizzle-kit …` | Yes on 1.3.11, **No on 1.4.2** (behavior change) |
| `bun --env-file=.env.development.local run <script>` | Yes (explicit file propagates to child processes) |
| `bun scripts/foo.ts` (Bun is the runtime) | Yes; with NODE_ENV unset, `.env.development.local` beats `.env.local` (same order as `next dev`) |

Conclusion: Bun auto-loading does **not** remove the need for explicit env loading in `drizzle.config.ts`. Use `@next/env`
`loadEnvConfig` (Next docs: https://nextjs.org/docs/app/guides/environment-variables#loading-environment-variables-with-nextenv).
Note `loadEnvConfig(dir)` without the 2nd arg uses **production** mode (skips `.env.development.local`); pass `dev=true` (source read in
@next/env 16.3.6). `dotenv` is not needed. For a local production build against the dev branch:
`bun --env-file=.env.development.local run build`.

## 10. Migrations workflow (solo dev + preview deployments)

Guides: Drizzle options 1–6 https://orm.drizzle.team/docs/pg/migrations · migrate https://orm.drizzle.team/docs/pg/drizzle-kit-migrate ·
push https://orm.drizzle.team/docs/pg/drizzle-kit-push · Neon + Drizzle https://neon.com/docs/guides/drizzle ·
Neon migrations https://neon.com/docs/guides/drizzle-migrations · Neon Vercel preview flow (build step) https://neon.com/docs/guides/vercel-managed-integration

1. Change `lib/db/schema.ts` → `bun run db:generate` → review SQL → commit `drizzle/<ts>_<name>/`.
2. `bun run db:migrate` → dev branch. Never `push` to dev/preview/prod (push + later migrate = "already exists" conflicts).
   `push` is fine only on throwaway DBs (PGlite, a scratch branch).
3. Push git branch → Vercel creates `preview/<branch>` from `main` (includes prod data) → build runs `drizzle-kit migrate` on it.
4. Merge → production build runs `drizzle-kit migrate` on `main`, then `next build`.
5. Drift control: `bun run db:check` in CI; `bun run db:drift` (`push --explain`, read-only) against a branch should print
   "No changes detected" (verified; needs `schemaFilter: ["public"]`). Neon: `neon branches schema-diff` / `neon diff`, or
   `neondatabase/schema-diff-action`.
6. Safety: migrations run before the new code is live and Vercel Instant Rollback does not roll back the DB → write
   **expand/contract** (additive first, destructive in a later deploy). Before risky migrations take the Free plan's 1 manual snapshot;
   Free history (instant restore) window = 6 h.
7. If a PR's migration is edited after it ran on its preview branch: `neon branches reset preview/<branch> --parent` (or delete the
   branch) and redeploy.
8. Drizzle migrator facts (rc.4 source): all pending migrations run in **one transaction**, **no advisory lock** (two concurrent builds on
   the same branch can race → rerun). Consequences: no `CREATE INDEX CONCURRENTLY`; a new enum value cannot be used in the same batch.

## 11. Neon Free plan: limits that matter here

Source: https://neon.com/pricing.md , https://neon.com/docs/introduction/plans , https://neon.com/docs/introduction/scale-to-zero
(Vercel-managed plan `free_v3` assumed identical — UNVERIFIED.)

- 100 CU-hours/project/month; 0.25 CU min → 400 h. **If the DB is touched at least every 5 min around the clock it never sleeps:
  0.25 CU × 730 h = 182.5 CU-h → quota gone mid-month → compute suspended until next period.** All branches' computes count.
- Scale to zero after 5 min (fixed on Free); cold start "a few hundred ms".
- Storage 0.5 GB/project (exceed → writes blocked). History 6 h (1 GB). 1 manual snapshot.
- Egress 5 GB/project (exceed → compute suspended). Tile payload math: 150 tiles as objects ≈ 6.2 KB; a 24-mark page ≈ 145 KB →
  ~33 700 uncached page loads per 5 GB. As tuples `[shape, rot/90, fg, bg]` ≈ 1.6 KB → ~127 000.
- 10 branches/project, hard cap on Free (no extra branches) → main + dev + ≤ 8 previews; limit blocks branch creation → with
  "Resource must be active before deployment" the preview deployment cannot proceed.
- Autoscaling up to 2 CU → cap max in Vercel Storage settings.

Mitigations: cache reads with `'use cache'` + `cacheTag` + `updateTag`; no per-page-view DB writes (use Vercel Analytics or a daily
rollup written rarely); compact tile encoding (optional); cleanup Action for preview branches.

## 12. Rate limiting without Redis

| Option | Fit |
|---|---|
| **SQL count per `ip_hash` (1 h window) + global pending cap** (above) | **Pick.** Exact window, zero extra infra, indexed, unit-testable, works in preview/local. Small race (2 parallel requests may pass) — acceptable; for strict: `db.transaction` + `pg_advisory_xact_lock(hashtext(ip_hash))` (verified). |
| Vercel WAF rate limit (dashboard rule or `@vercel/firewall` `checkRateLimit`) | Optional outer shield vs floods. Hobby: **1** rate-limit rule/project (3 custom rules total), fixed window **10 s–10 min** (no 1-hour window below Enterprise), keys IP/JA4, 1 M allowed requests included; counters per region; SDK in previews needs Protection Bypass for Automation. https://vercel.com/docs/vercel-firewall/vercel-waf/rate-limiting , https://vercel.com/docs/vercel-firewall/vercel-waf/rate-limiting-sdk |
| Keep Upstash + `@upstash/ratelimit` 2.2.0 | Extra service, env vars and failure point for a few requests/hour. Not worth it now. |

Privacy: IP hashes are still personal data → HMAC with a secret (`IP_HASH_SECRET`, `openssl rand -base64 32`), then null `ip_hash`
for rows older than 24 h (e.g. in `after()` of the submit action — no cron needed). IPv6: consider hashing the /64 prefix.
Hard-deleting spam rows also removes them from the count (limit is per remaining rows) — acceptable.

## 16. Gotchas (verified unless marked)

- **G1** drizzle-kit (0.31.11 and 1.0.0-rc.4) emits `DESC NULLS LAST` for `.desc()` index columns, but `orderBy(desc(col))` sorts
  `DESC` (nulls first) → planner ignores the index (Seq Scan + Sort in EXPLAIN). Use `.desc().nullsFirst()` in the index.
- **G2** Vercel CLI `integration add neon` defaults `auth=true` (Neon Auth) and connects Development → pass `-m auth=false -e production -e preview`.
- **G3** drizzle-kit v1 `push` manages all schemas: with a `neon_auth` schema present it asks to drop it ("confirm_data_loss … neon_auth").
  Fix: `schemaFilter: ["public"]`.
- **G4** Connecting Preview **without** preview branching gives previews the production branch → preview builds would migrate prod.
- **G5** Vercel-managed preview branches may never auto-delete (last-20-previews exception) and Free caps at 10 branches → add
  `neondatabase/delete-branch-action@v3` on `pull_request: closed` (branch `preview/${{ github.head_ref }}`, needs `NEON_PROJECT_ID`
  var + `NEON_API_KEY` secret). Bot PRs (Renovate/Dependabot) also create branches.
- **G6** drizzle-kit reads no `.env*`; Bun auto-loading does not reach it (Bun 1.4 also disables it under `--bun`) → `@next/env` in config.
- **G7** `@next/env` `loadEnvConfig(dir)` defaults to production mode → pass `true` for dev files.
- **G8** pg 8.23 prints `SECURITY WARNING: The SSL modes 'prefer', 'require', and 'verify-ca' are treated as aliases for 'verify-full'`
  for Neon URLs (`sslmode=require`); pg v9 will switch to weaker libpq semantics. Also `channel_binding=require` in the URL is parsed
  but **not** applied by pg (needs `enableChannelBinding: true`; with Neon pooler UNVERIFIED). Normalize to `sslmode=verify-full`.
- **G9** Biome fails on generated `snapshot.json` → `"!drizzle"` in `biome.json` includes.
- **G10** `@neondatabase/serverless` ≥1.0: `sql("… $1", [x])` throws; use tagged template or `sql.query()`. Vercel's CLI guide still shows the old form.
- **G11** Migrations run inside one transaction, no lock (§10.8).
- **G12** Neon CLI on Vercel-managed org: API key only (`neon login` fails).
- **G13** `vercel integration add` also installs Neon agent skills (paths UNVERIFIED) — review the diff.
- **G14** Drizzle `beta` dist-tag points to old 1.0.0-beta.22; use exact `1.0.0-rc.4` (or `@rc`).
- **G15** Open bug #6241/#6341: pooled `transaction()` leaks a client when `BEGIN` fails (0.45.x and rc.4).
- **G16** `'use cache'` DB reads can run during `next build` → keep `db:migrate` before `next build` in `buildCommand`.
